## 目标

创建项目级技能 `slurm-job-operator`，指导 Agent 安全地准备、提交、监控和验证 Slurm 作业，避免环境初始化缺失、重复提交、覆盖产物和错误恢复不当。

## 范围

- 适用于 Slurm、`sbatch`、GPU/CPU 计算节点、远程 Conda 环境和长时间任务。
- 允许在用户已明确要求执行任务时自动提交和验证。
- 不自动取消其他作业，不操作其他用户资源，不覆盖已有输出。
- 不替代项目的具体运行文档；任务参数仍以项目文档和脚本帮助信息为准。

## 操作流程

1. 只读检查分区、当前用户作业、目标文件、环境和输出目录。
2. 为小样本创建独立的作业名、日志路径和输出目录。
3. 生成可审阅的 `sbatch` 脚本，显式设置最小必要资源。
4. 批处理脚本先执行 `source /etc/profile.d/modules.sh`，再加载模块。
5. 使用 Conda 可执行文件的绝对路径调用 `conda run`，不依赖交互式 shell 初始化。
6. 提交前执行 shell 语法检查；提交后立即记录并查询 Job ID。
7. 仅通过 Job ID 监控状态。MCP 超时、连接断开或查询异常不能视为作业失败。
8. 作业进入终态后检查 `sacct`、标准输出、错误日志和产物。
9. 成功时验证产物数量、命名、可读性和关键内容。
10. 失败时先定位日志中的首个根因，只修改一个因素后再提交新作业。

## 状态与恢复

- `PENDING`、`RUNNING`、`COMPLETING`：禁止重复提交。
- `COMPLETED` 且退出码为 `0:0`：继续验证产物，不能只凭状态宣告成功。
- `FAILED`、`TIMEOUT`、`OUT_OF_MEMORY`、`CANCELLED`：读取日志和资源统计后分类处理。
- 无法在 `squeue` 中找到作业：使用 `sacct` 判断历史终态，不直接重提。
- 每次重提必须使用新的 Job ID，并保留旧日志作为诊断证据。

## 安全约束

- 登录节点仅执行轻量检查、脚本准备和作业提交。
- GPU 工作负载必须由 Slurm 分配计算节点。
- 一次远程调用只完成一个目的；改变状态后使用独立调用验证。
- 禁止将密钥写入脚本、日志或仓库。
- 禁止使用破坏性命令清理未知产物。

## 验收

- 技能位于 `.trae/skills/slurm-job-operator/SKILL.md`。
- frontmatter 名称与目录一致，描述包含触发场景和排除场景。
- 技能明确覆盖 Modules 初始化、绝对 Conda 路径、Job ID、日志和产物验证。
- 技能明确禁止对活动作业重复提交。
- 技能能够指导 Agent 从失败日志中修复单一根因并安全重提。
