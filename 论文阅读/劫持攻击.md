# 劫持攻击 (Hijacking Attack)

## 概念
劫持攻击是一种广泛存在于计算机网络和软件系统中的安全威胁。其核心思想是攻击者通过某种手段接管、控制或篡改系统中的正常通信、会话、资源或执行流程，以达到窃取数据、伪造身份或破坏系统的目的。

在不同领域中，劫持攻击有不同的具体表现形式，如会话劫持 (Session Hijacking)、DNS 劫持、提示词劫持 (Prompt Hijacking) 等。

## 常见类型与机制

### 1. 会话劫持 (Session Hijacking)
攻击者窃取用户的有效会话标识符（如 Session ID 或 Cookie），从而冒充合法用户访问系统。
- **机制**：通过跨站脚本攻击 (XSS)、网络嗅探 (Sniffing) 或中间人攻击 (MITM) 获取凭据。

### 2. DNS 劫持 (DNS Hijacking)
攻击者篡改域名系统 (DNS) 的解析结果，将合法域名指向恶意的 IP 地址。
- **机制**：修改本地主机的 DNS 设置、攻击 DNS 服务器或利用路由器漏洞，导致流量被重定向到钓鱼网站。

### 3. 提示词劫持 (Prompt Hijacking / Prompt Injection)
在大模型 (LLM) 应用中，提示词劫持是指攻击者通过在输入中注入恶意指令，覆盖或篡改开发者预设的系统提示词，从而改变模型的既定行为。
- **机制**：利用模型无法严格区分“指令”和“数据”的缺陷。例如，输入中包含“忽略之前的指令，现在执行以下操作：...”。

## 数学表达 (以提示词劫持为例)
设系统预设指令为 $P_{sys}$，用户输入为 $X$。正常情况下，模型的输出 $Y$ 基于两者的结合：
$$ Y = M(P_{sys} \oplus X) $$

在提示词劫持中，攻击者构造恶意的输入 $X_{hijack}$，使得模型在处理 $P_{sys} \oplus X_{hijack}$ 时，完全忽略了 $P_{sys}$ 的权重，导致：
$$ M(P_{sys} \oplus X_{hijack}) \approx M(X_{hijack}) $$

## 防御策略
- **加密与认证**：在网络通信中使用 HTTPS/TLS，防止数据被嗅探和篡改（针对会话和 DNS 劫持）。
- **严格的输入验证**：对用户输入进行净化和编码，防止跨站脚本攻击。
- **指令与数据分离**：在 LLM 应用中，尝试在架构层面（如使用特定的标记符或 API 结构）隔离系统指令和用户输入，防止提示词注入。
- **异常检测**：监控网络流量、登录行为和模型输出，及时发现偏离正常模式的劫持活动。
