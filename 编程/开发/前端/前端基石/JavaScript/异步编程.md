## 同步与异步

JavaScript 是一门单线程语言，意味着在同一时间内只能执行一个任务。如果所有任务都同步执行，遇到耗时操作（如网络请求、文件读取）时就会导致线程阻塞。

为了解决这个问题，JavaScript 引入了异步编程机制。异步操作不会阻塞主线程，而是在操作完成后，通过事件循环（Event Loop）机制将回调函数推入任务队列中等待执行。

## 异步编程的发展历程

### 回调函数 (Callback)

早期的异步编程主要依赖回调函数。将函数作为参数传递给异步操作，在操作完成后调用该函数。
缺点：多个异步操作依赖时，容易形成回调地狱（Callback Hell），导致代码呈金字塔状横向发展，难以维护和阅读。

**回调地狱示例**：
假设我们需要依次完成三个相互依赖的异步任务：获取用户ID -> 根据ID获取文章列表 -> 获取第一篇文章的详情。

```javascript
// 典型的回调地狱：嵌套过深，错误处理分散
getUserInfo("user_123", function(err, user) {
  if (err) {
    console.error("获取用户信息失败", err);
    return;
  }
  
  getArticles(user.id, function(err, articles) {
    if (err) {
      console.error("获取文章列表失败", err);
      return;
    }
    
    getArticleDetail(articles[0].id, function(err, detail) {
      if (err) {
        console.error("获取文章详情失败", err);
        return;
      }
      
      console.log("最终获取到的文章详情：", detail);
    });
  });
});
```

如上图所示，当异步任务增加时，代码的缩进会越来越深，这种代码结构使得错误处理（每个嵌套层都需要单独处理 `err`）和逻辑追踪变得极其困难。这也是促使 Promise 诞生的核心原因。

### Promise 核心语法与机制

Promise 是 ES6 引入的用于处理异步操作的对象。可以将其理解为一个“承诺”，代表了一个异步操作的最终完成或失败及其结果值。它本质上是一个状态机。

#### 1. Promise 的三种状态
Promise 在其生命周期中只处于以下三种状态之一：
- **Pending（进行中）**：初始状态，操作尚未完成。
- **Fulfilled（已成功）**：操作成功完成（有时也称为 Resolved）。
- **Rejected（已失败）**：操作失败。

**状态不可逆性**：Promise 的状态一旦由 Pending 变为 Fulfilled 或 Rejected，就会被“冻结”，不再发生任何改变。

#### 2. Promise 的创建（构造函数）
使用 `new Promise()` 实例化一个 Promise 对象。构造函数接收一个执行器函数（Executor）作为参数，该函数会立即同步执行，并接收两个参数：`resolve` 和 `reject`。

```javascript
const myPromise = new Promise((resolve, reject) => {
  // 这里通常包含异步操作，例如定时器、网络请求等
  setTimeout(() => {
    const isSuccess = Math.random() > 0.5;
    
    if (isSuccess) {
      // 成功时调用 resolve，将状态变为 Fulfilled，并传递结果值
      resolve("操作成功获取的数据");
    } else {
      // 失败时调用 reject，将状态变为 Rejected，并传递错误原因
      reject(new Error("操作失败的原因"));
    }
  }, 1000);
});
```

#### 3. Promise 的消费（实例方法）
创建 Promise 后，通过实例方法来处理成功或失败的结果。

- **`.then(onFulfilled, onRejected)`**：用于注册状态改变时的回调。通常只传入 `onFulfilled` 来处理成功逻辑。
- **`.catch(onRejected)`**：专门用于捕获 Rejected 状态及处理前序链条中抛出的异常，是 `.then(null, onRejected)` 的语法糖。
- **`.finally(onFinally)`**：无论 Promise 最终状态是成功还是失败，都会执行的回调，常用于清理工作（如关闭 Loading 动画）。

```javascript
myPromise
  .then(data => {
    console.log("处理成功:", data);
  })
  .catch(error => {
    console.error("处理失败:", error.message);
  })
  .finally(() => {
    console.log("无论成功或失败，操作已结束。");
  });
```

#### 4. 链式调用解决回调地狱
`.then()` 和 `.catch()` 方法每次都会**返回一个新的 Promise 对象**。这使得可以将多个异步操作链接在一起，从而将原本嵌套的回调地狱展平为线性的链式调用。

```javascript
// 使用 Promise 链式调用重写前文的回调地狱
getUserInfoPromise("user_123")
  .then(user => {
    // 返回一个新的 Promise 供下一个 then 消费
    return getArticlesPromise(user.id);
  })
  .then(articles => {
    return getArticleDetailPromise(articles[0].id);
  })
  .then(detail => {
    console.log("最终获取到的文章详情：", detail);
  })
  // 集中捕获整条链上的任何错误，无需在每一步单独处理
  .catch(err => {
    console.error("链条中发生错误：", err);
  });
```

#### 5. 常用静态方法
Promise 还提供了一些静态方法来处理多个并发的异步任务：
- **`Promise.all(iterable)`**：等待所有 Promise 成功才成功（返回结果数组），若有一个失败则立即失败。
- **`Promise.race(iterable)`**：返回最先改变状态的 Promise（无论是成功还是失败）。
- **`Promise.allSettled(iterable)`**：等待所有 Promise 都已敲定（Settled，即不论成功或失败）后才完成，并返回所有结果的描述数组。

### async/await

`async/await` 是基于 Promise 的 ES2017 (ES8) 语法糖，使异步代码看起来像同步代码。
- `async` 关键字用于声明一个异步函数，该函数总是返回一个 Promise。
- `await` 关键字只能在 `async` 函数内部使用，用于等待一个 Promise 解析完成。
这种方式极大地提高了异步代码的可读性和可维护性，是目前处理异步操作的主流方案。

```javascript
// async/await 示例：结合 try...catch 进行错误处理
const loadData = async () => {
  try {
    console.log("开始加载数据...");
    const result = await fetchData(); // 等待 Promise 解析
    console.log("成功:", result.data);
  } catch (error) {
    console.error("捕获到错误:", error.message);
  } finally {
    console.log("数据加载流程结束。");
  }
};

loadData();
```
