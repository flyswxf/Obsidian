## DOM 的概念

DOM（Document Object Model，文档对象模型）是 HTML 和 XML 文档的编程接口。它将网页转化为一个由节点和对象组成的结构集合，使得程序可以改变文档的结构、样式和内容。

## DOM 树结构图示

为了更好地理解 DOM 树，我们来看一段基础的 HTML 代码：

```html
<!DOCTYPE html>
<html>
  <head>
    <title>DOM树</title>
    <meta charset="UTF-8">
  </head>
  <body>
    <h1>标题</h1>
    <p>段落内容</p>
  </body>
</html>
```

当浏览器解析上述 HTML 代码时，会生成如下的 DOM 树结构：

![[dom_tree.svg]]

在上图中：
- **元素节点（Element Node）**：如 `<html>`、`<head>`、`<title>` 等蓝色的矩形框，它们代表了 HTML 标签。
- **文本节点（Text Node）**：如 `"DOM树"`、`"标题"` 等黄色的椭圆框。在 DOM 中，标签内部的文字并不是标签本身的一部分，而是作为该标签的**子节点**（文本节点）存在。

## 解析过程

当浏览器接收到 HTML 文档后，会进行以下步骤将其解析为 DOM 树：

1. **字节流解码**：浏览器将接收到的字节数据按照指定的字符编码（如 UTF-8）解码为字符。
2. **词法分析（Tokenization）**：将字符流转换为各种标记（Token），如起始标签、结束标签、文本内容等。
3. **构建节点（Node）**：将标记转换为 DOM 节点对象，每个节点包含了标签的属性和相关信息。
4. **构建 DOM 树**：根据节点之间的嵌套关系，将节点连接成树状结构，形成最终的 DOM 树。

## 解析时的阻塞

在解析 HTML 的过程中，如果遇到外部资源（如脚本文件、样式表），可能会影响 DOM 树的构建：

- **CSS 阻塞**：CSS 文件的加载和解析不会阻塞 DOM 树的构建，但会阻塞渲染树（Render Tree）的构建，同时也会阻塞后续脚本的执行。
- **JavaScript 阻塞**：默认情况下，遇到 `<script>` 标签时，浏览器会暂停 DOM 解析，先下载并执行脚本，然后再继续解析 DOM。这是因为脚本可能会通过 `document.write` 等方式修改 DOM 结构。

### 优化脚本加载

为了避免 JavaScript 阻塞 DOM 解析，可以使用以下属性：
- `defer`：脚本会异步下载，但会延迟到整个文档解析完毕后再按顺序执行。
- `async`：脚本会异步下载，下载完成后立即执行，执行顺序不确定。
