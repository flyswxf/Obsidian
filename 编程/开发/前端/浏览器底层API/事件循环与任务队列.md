## 核心运行机制

JavaScript 在浏览器中是单线程执行的。为了在不阻塞主线程的情况下处理网络请求、定时器等异步操作，浏览器实现了事件循环（Event Loop）机制。

事件循环本质上是一个持续运行的循环，它不断地检查调用栈（Call Stack）是否为空。如果调用栈为空，它就会去检查任务队列（Task Queue）中是否有待处理的任务。如果有，就将其取出并推入调用栈中执行。

## 宏任务与微任务

任务队列并非单一队列，而是分为两种类型：宏任务（Macrotask）和微任务（Microtask）。它们的优先级和执行时机有着严格的区别。

### 宏任务 (Macrotask)
宏任务通常代表一些离散的、独立的工作单元。每次事件循环的迭代（Tick）会执行**一个**宏任务。
常见的宏任务包括：
- 整体代码脚本（Script 解析运行）
- `setTimeout` 与 `setInterval`
- `setImmediate`（仅 Node.js）
- UI 交互事件（如点击、滚动）
- 网络请求回调（如 Ajax、Fetch）

### 微任务 (Microtask)
微任务通常用于处理需要在当前宏任务执行结束后、但在浏览器渲染之前必须立刻完成的更新。
常见的微任务包括：
- `Promise.then`、`.catch`、`.finally`
- `MutationObserver`
- `process.nextTick`（仅 Node.js）
- `queueMicrotask`

## 执行顺序 (Tick 流程)

一次完整的事件循环 Tick 流程如下：

1. **执行宏任务**：从宏任务队列中取出一个任务执行（初次执行时，通常是整段 Script 代码）。
2. **清空微任务队列**：宏任务执行完毕后，事件循环会立即检查微任务队列。它会连续执行队列中的**所有**微任务，直到微任务队列完全为空。如果在执行微任务的过程中又产生了新的微任务，这些新微任务也会在当前阶段被一并执行完毕。
3. **视图渲染**：微任务队列清空后，浏览器会判断是否需要进行 UI 渲染（通常受浏览器的刷新率控制，如 60Hz 屏幕下约每 16.6ms 渲染一次）。
4. **下一轮循环**：渲染完成后，事件循环进入下一个 Tick，回到步骤 1，提取下一个宏任务。

这种机制保证了在进行 DOM 渲染之前，所有与数据相关的微任务状态更新都能被同步计算完毕，避免了中间无效的渲染开销。
