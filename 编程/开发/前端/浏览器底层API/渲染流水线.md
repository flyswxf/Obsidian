浏览器将HTML、CSS和JavaScript转换为屏幕上实际像素的过程称为渲染流水线（Rendering Pipeline）。这一过程高度复杂且各个阶段紧密相连。

## 构建DOM树
浏览器接收到HTML字节流后，经过解码、分词、解析，最终在内存中构建出[[DOM树解析|DOM树]]。它是页面结构的内部表示，也是JavaScript操作页面的基础。

## 构建CSSOM树
解析HTML的同时，若遇到CSS样式（包括内联样式、`<style>`标签及外部样式表），浏览器会将其转换为 CSS对象模型(CSSOM树)。它不仅包含开发者定义的样式，还包含浏览器默认样式。

## 构建渲染树
将DOM树和CSSOM树结合，生成渲染树（Render Tree）。渲染树仅包含需要显示的节点及其对应的样式信息。例如，`display: none`的节点会被忽略。

## 布局计算 (Layout)

依据渲染树，计算每个节点在屏幕上的确切几何位置和尺寸。如果后续操作改变了元素的几何属性，将触发[[重排与重绘#重排（Reflow）|布局重新计算]]，这是一个性能开销较大的过程。

## 绘制（Paint）

将渲染树转化为屏幕上的实际像素。浏览器会将页面分解为多个图层（Layers），对每个图层生成绘制记录，确定绘制顺序和内容。当元素的非几何属性（如颜色）改变时，会触发[[重排与重绘#重绘（Repaint）|重新绘制]]。

```javascript
// 触发重绘（Paint）但不触发重排的操作
const box = document.getElementById('box');
// 仅修改外观属性
box.style.backgroundColor = 'red';
box.style.color = 'blue';
```

## 合成（Composite）
最后，合成线程将各个图层合并，并将其栅格化（Rasterize）显示在屏幕上。利用GPU加速可以显著提升图层合成的效率。
