V8引擎的垃圾回收（Garbage Collection, GC）机制基于分代假设：大部分对象生命周期极短，少数对象存活时间较长。因此，V8将堆内存划分为新生代和老生代，分别采用不同的回收策略以优化性能。

## 内存分代
- **新生代（New Space）**：存放存活时间短的对象，内存容量较小。
- **老生代（Old Space）**：存放存活时间长或体积较大的对象，内存容量较大。

## 新生代回收策略
新生代采用Scavenge算法。将内存分为两个等大区域：使用区（From）和空闲区（To）。
1. 在From区分配对象。
2. 垃圾回收时，检查From区中的存活对象。
3. 将存活对象复制到To区，并紧缩排列，解决内存碎片问题。
4. 清空From区，随后From区与To区角色互换。
若对象经过多次复制依然存活，或To区空间占用超过阈值，该对象会被晋升至老生代。

```text
// 伪代码：Scavenge 算法核心逻辑
function scavenge() {
  for (let obj of FromSpace) {
    if (isAlive(obj)) {
      if (shouldPromote(obj)) {
        promoteToOldSpace(obj);
      } else {
        copyToToSpace(obj);
      }
    }
  }
  clear(FromSpace);
  swap(FromSpace, ToSpace);
}
```

## 老生代回收策略
老生代采用标记-清除（Mark-Sweep）和标记-整理（Mark-Compact）相结合的算法。
- **标记-清除**：遍历堆中的所有对象，标记存活对象。随后清除未被标记的死亡对象。此过程会产生内存碎片。
- **标记-整理**：当内存碎片过多，无法分配大对象时触发。将所有存活对象向一端移动，然后清理掉边界外的内存。

## 优化机制
传统的垃圾回收会阻塞JavaScript主线程（全停顿，Stop-The-World）。V8引入了多种优化手段：
- **并行回收（Parallel）**：主线程与多个辅助线程同时执行垃圾回收，缩短停顿时间。
- **并发回收（Concurrent）**：辅助线程在后台执行垃圾回收，主线程继续执行JavaScript代码。
- **增量回收（Incremental）**：将垃圾回收拆分为多个小任务，穿插在JavaScript执行之间进行。
