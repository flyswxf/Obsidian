## 核心概念

热模块替换（Hot Module Replacement，简称 HMR）允许在应用运行过程中替换、添加或删除模块，而无需重新加载整个页面，从而保持应用的状态。Vite 的 HMR 基于原生 [[ESM与前端模块化|ESM]] 实现，具有极快的更新速度。

## 实现机制

Vite 的 HMR 机制主要包含以下步骤：

1. **建立通信通道**：启动本地服务器时，通过 WebSocket 建立浏览器与服务端的双向连接。
2. **监听文件变更**：使用文件系统监听工具（如 chokidar）监控源码变动。
3. **构建更新模块**：当文件发生修改时，服务器准确定位变更的模块，并生成更新的模块代码。
4. **推送更新通知**：通过 WebSocket 向浏览器发送更新消息（通常包含模块的 URL 和更新类型）。
5. **客户端热替换**：浏览器接收到更新通知后，利用动态 `import()` 请求最新的模块代码，并在客户端执行替换逻辑。

## 边界处理

在某些情况下，模块无法被热替换（例如修改了全局状态或缺少 HMR 接收器）。此时，Vite 会触发完整的页面刷新（Full Reload）以确保应用状态的正确性。

```javascript
// HMR 接收器示例
if (import.meta.hot) {
  // 接受当前模块的更新
  import.meta.hot.accept((newModule) => {
    // 可以在这里执行更新逻辑
    console.log('模块已更新', newModule);
  });

  // 处理模块被废弃的情况
  import.meta.hot.dispose(() => {
    // 清理副作用，例如定时器或事件监听
  });
}
```
