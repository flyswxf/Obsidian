## 规则的基本结构

自定义 ESLint 规则本质上是一个暴露特定接口的 JavaScript 对象。核心包含 `meta` 和 `create` 两个部分。

```javascript
module.exports = {
    meta: {
        type: "suggestion", // 规则类型：problem, suggestion, layout
        docs: {
            description: "描述规则的功能",
            category: "Best Practices",
            recommended: false
        },
        fixable: "code", // 如果规则支持自动修复，需指定为 "code" 或 "whitespace"
        schema: [] // 规则的配置选项
    },
    create(context) {
        return {
            // 返回一个对象，包含 AST 节点选择器及其对应的回调函数
            Identifier(node) {
                if (node.name === "foo") {
                    context.report({
                        node,
                        message: "禁止使用变量名 foo",
                        fix(fixer) {
                            return fixer.replaceText(node, "bar");
                        }
                    });
                }
            }
        };
    }
};
```

## 核心 API

- **`context.report()`**：用于发布警告或错误信息。必须提供引发问题的 [[AST抽象语法树解析|AST]] 节点和错误描述。
- **`fixer`**：提供了一系列方法（如 `insertTextAfter`、`replaceText` 等），用于实现代码的自动修复逻辑。

## 测试驱动开发

编写自定义规则时，强烈建议配合 `RuleTester` 工具。通过定义一系列有效（valid）和无效（invalid）的代码片段，可以快速验证规则的正确性并防止回归。
