## 装饰器概念

装饰器（Decorator）是一种特殊类型的声明，它能够被附加到类声明、方法、访问符、属性或参数上。本质上，装饰器是一个在运行时执行的函数，能够动态地修改或增强目标对象的行为。

要启用装饰器特性，需要在 `tsconfig.json` 中开启 `experimentalDecorators` 编译选项。随着 ECMAScript 标准的演进，TypeScript 对装饰器的支持也在不断发展。

## 工作原理

装饰器的执行时机主要是在代码加载阶段，而不是每次实例化时。其核心原理依赖于 `Object.defineProperty` 或现代 JavaScript 引擎的元编程能力。

### 装饰器工厂

如果需要向装饰器传递参数，可以编写一个装饰器工厂函数。该函数执行后返回一个真正的装饰器函数。

```typescript
function Logger(prefix: string) {
  return function (target: Function) {
    console.log(`${prefix}: ${target.name}`);
  };
}

@Logger('DEBUG')
class MyService {}
```

## 装饰器分类

### 类装饰器
应用于类的构造函数，可以用来监视、修改或替换类定义。常用于依赖注入框架中，以标记类的元数据。结合[[泛型高级用法|泛型]]，能够实现强大的类型安全的依赖注册。

### 方法装饰器
应用于方法的属性描述符，可用于拦截方法调用、修改输入输出或进行权限校验。

```typescript
function LogExecutionTime(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value;
  descriptor.value = function (...args: any[]) {
    const start = performance.now();
    const result = originalMethod.apply(this, args);
    const end = performance.now();
    console.log(`Execution time: ${end - start} ms`);
    return result;
  };
}
```

### 属性与参数装饰器
- **属性装饰器**：常用于依赖注入或属性的观察。
- **参数装饰器**：应用于类构造函数或方法声明的参数，主要用于为路由控制器或验证器提供元数据，通常需配合 `reflect-metadata` 库进行高级[[类型系统与类型体操|类型处理]]。

## 结合元数据

现代框架（如 NestJS）深度依赖 `Reflect` API 与装饰器的结合。通过在装饰器中附加元数据，可以在运行时提取并利用这些信息进行动态路由、验证和依赖注入，从而极大地提升了开发效率与架构灵活性。
