## 类型系统概述

TypeScript 的核心在于其强大的静态类型系统，旨在编译阶段捕获错误。它基于结构化类型系统（鸭子类型），即只要结构契合，即被视为同等类型。类型系统不仅提供了基础的类型注解，还通过支持[[泛型高级用法|泛型]]实现了高度的代码复用。

核心概念包括：
- **基础类型**：`string`, `number`, `boolean`, `symbol`, `null`, `undefined` 等。
- **复合类型**：对象（`object`，`interface`，`type`）、数组、元组（Tuple）。
- **特殊类型**：`any`（跳过检查）、`unknown`（安全的 `any`）、`never`（不可达类型）、`void`（无返回值）。

## 类型体操

类型体操是指利用 TypeScript 强大的类型推导和操作能力，在类型级别进行复杂的逻辑运算。其本质是**在类型层面进行编程**，将类型视为变量，通过内置工具或自定义规则推导出新的类型。

### 核心机制

1. **条件类型**：允许基于条件进行类型推导，类似于三元运算符。
   ```typescript
   type IsString<T> = T extends string ? true : false;
   ```
2. **模式匹配（infer）**：在条件类型中，使用 `infer` 关键字提取特定部分的类型。
   ```typescript
   type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any;
   ```
3. **映射类型**：遍历已有类型的键，生成新的对象类型。常结合 `keyof` 和索引访问类型。
   ```typescript
   type Readonly<T> = {
     readonly [P in keyof T]: T[P];
   };
   ```
4. **模板字面量类型**：对字符串类型进行拼接和模式匹配。
   ```typescript
   type EventName<T extends string> = `${T}Changed`;
   ```

### 经典案例

在复杂的框架开发中，类型体操被广泛应用。例如实现深度只读、对象键值的递归处理等操作。虽然类型体操能够极大地增强类型的严谨性，但过度复杂的类型推导可能导致编译性能下降，并在应用[[装饰器原理|装饰器]]等高级特性时增加维护成本。因此，需在类型安全与可读性之间保持平衡。

```typescript
// 深度只读的类型体操实现
type DeepReadonly<T> = {
  readonly [P in keyof T]: T[P] extends object 
    ? DeepReadonly<T[P]> 
    : T[P];
};

interface Config {
  env: string;
  db: { host: string; port: number };
}

const config: DeepReadonly<Config> = {
  env: 'prod',
  db: { host: 'localhost', port: 3306 }
};
// config.db.port = 3307; // 编译报错：无法分配到 "port" ，因为它是只读属性。
```
