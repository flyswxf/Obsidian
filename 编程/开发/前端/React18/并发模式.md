## 并发特性概述

并发模式（Concurrent Mode）是 React 18 带来的一项底层革新。它并不意味着 React 在同一时刻真正同时执行多个任务（JavaScript 依然是单线程的），而是赋予了 React 能够暂停、恢复甚至放弃某个渲染任务的能力。

基于[[Fiber架构解析#渲染流程|Fiber的可中断渲染机制]]，React 可以根据任务的优先级动态调度执行权，从而在执行复杂渲染时依然保持页面的极速响应。

## 核心机制：时间切片

在传统同步渲染中，一旦开始更新组件树，主线程就会被一直占用。并发模式通过时间切片（Time Slicing）将长任务拆解为多个小任务。每次仅执行一小段代码（通常是几毫秒），随后主动将控制权交还给浏览器，让浏览器有机会处理用户输入、页面滚动和动画绘制。当浏览器空闲时，React 再继续剩余的渲染工作。

## 关键并发 API

React 18 提供了一系列新的 API 来帮助开发者利用并发特性：

### useTransition

用于区分紧急更新与非紧急更新。例如，在搜索框中输入字符属于紧急更新（需立即在输入框反馈），而根据搜索词过滤大量数据则属于非紧急更新。

```javascript
const [isPending, startTransition] = useTransition();

// 紧急更新：直接设置搜索词
setInputValue(text);

startTransition(() => {
  // 非紧急更新：过滤数据
  setSearchQuery(text);
});
```

通过 `startTransition` 包装的更新会被标记为低优先级，若在此期间发生更高优先级的交互，当前渲染会被安全中断。

### useDeferredValue

当无法直接控制状态的更新过程（例如状态来源于外部属性）时，可以使用 `useDeferredValue` 接收一个状态值，并返回该值的延迟版本。在主线程繁忙时，延迟值会保持旧状态，待高优先级任务结束后再同步更新。

## 并发模式下的安全考量

在引入并发模式后，组件可能会经历多次被中断和重启的 Render 阶段。因此，必须确保组件函数是**纯函数**，绝不能在 Render 阶段执行任何具有副作用的操作。所有的副作用（如网络请求、DOM 操作）都必须严格放置在 `useEffect` 或事件处理函数中。

此外，当使用外部状态库时，需防范“撕裂”（Tearing）现象，即同一时刻屏幕上展示了不一致的状态。此时可以采用 `useSyncExternalStore` 这一专门为并发环境设计的[[状态管理设计#与并发模式的兼容|外部状态同步Hook]]来保障渲染一致性。

## 现代 React 代码实践：useDeferredValue 的应用

在面对大量数据渲染时，直接基于用户输入过滤数据可能会导致输入框卡顿。通过 `useDeferredValue` 可以让输入框的更新保持高优先级，而列表的过滤渲染降级为低优先级任务。

```javascript
import { useState, useDeferredValue, useMemo } from 'react';

// 模拟一个包含大量数据的列表组件
function SlowList({ text }) {
  const items = useMemo(() => {
    const list = [];
    for (let i = 0; i < 5000; i++) {
      list.push(<li key={i}>Item {i}: {text}</li>);
    }
    return list;
  }, [text]);

  return <ul>{items}</ul>;
}

export default function ConcurrentDemo() {
  const [query, setQuery] = useState('');
  // 获取 query 的延迟版本
  const deferredQuery = useDeferredValue(query);

  // 判断是否正在后台进行低优先级渲染
  const isStale = query !== deferredQuery;

  return (
    <div>
      <input
        type="text"
        value={query}
        onChange={e => setQuery(e.target.value)}
        placeholder="搜索..."
      />
      <div style={{ opacity: isStale ? 0.5 : 1, transition: 'opacity 0.2s' }}>
        {/* 列表组件使用延迟后的值进行渲染 */}
        <SlowList text={deferredQuery} />
      </div>
    </div>
  );
}
```

在这个示例中，当用户快速输入时，`query` 立即更新以保证输入框响应，而 `deferredQuery` 会滞后更新。React 在后台使用[[Fiber架构解析#调度机制|时间切片]]机制计算新的列表结构，计算完成后再一次性更新到屏幕上。
