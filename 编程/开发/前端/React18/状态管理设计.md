## 状态管理的演进

在前端应用日趋复杂的背景下，状态管理方案经历了多次范式转移。从早期的 Redux 集中式管理，到基于 Context API 的轻量级方案，再到如今百花齐放的原子化与代理响应式方案，如何优雅地处理状态流转一直是架构设计的核心考量。

## 核心状态分类

为了更好地组织代码结构，通常需要将应用状态进行逻辑拆分：

1. **局部 UI 状态**：仅在单个组件或小范围组件树中使用的状态（如弹窗开关、表单输入）。此类状态直接使用内部 Hook（如 `useState`）维护即可。
2. **全局共享状态**：跨越多个层级、多个页面共享的数据（如用户信息、主题配置）。
3. **服务端缓存状态**：从后端 API 获取的数据。这类数据往往涉及请求状态（加载中、失败）、缓存失效与重新请求，推荐使用专门的查询库（如 React Query、SWR）来接管。

## 常见状态管理模式

### 集中式状态管理（如 Redux）

强调单一数据源和单向数据流。所有状态变更都必须通过分发动作（Dispatch Action）并由纯函数（Reducer）处理。虽然具有极强的可预测性和时间旅行调试能力，但往往伴随着大量的样板代码。

### 原子化状态管理（如 Jotai, Recoil）

采用自下而上的设计理念。状态被拆分为一个个微小的原子（Atom），组件只需订阅自身需要的原子状态。这种模式天然支持细粒度的依赖追踪，能有效避免不必要的组件重渲染，非常适合构建高性能的复杂交互界面。

### 代理与响应式方案（如 Zustand, MobX）

通过 Proxy 机制拦截数据的读取与修改，实现更加直观的面向对象编程体验。开发者可以直接修改状态对象，底层会自动收集依赖并触发相应组件的更新。

## 性能优化考量

在设计状态树时，应遵循状态最小化原则。能通过现有状态推导出的数据，绝不应作为独立状态存储，而是应借助 `useMemo` 等手段进行缓存计算。

### 与并发模式的兼容

随着[[并发模式|并发渲染特性]]的普及，状态管理库必须保证在可中断渲染过程中的数据一致性。React 18 提供的 `useSyncExternalStore` 钩子，使得第三方状态库能够在不触发副作用的前提下，安全地与 React 内部的[[Fiber架构解析#渲染流程|渲染机制]]进行同步，避免因高优先级任务打断而导致的 UI 状态撕裂。

## 现代 React 代码实践

### 基于 Context 与 useReducer 的轻量级状态管理

对于局部或中等规模的全局状态，结合 `Context` 和 `useReducer` 是一种原生的最佳实践：

```javascript
import { createContext, useContext, useReducer } from 'react';

// 1. 定义初始状态与 Reducer
const initialState = { user: null, theme: 'light' };
function appReducer(state, action) {
  switch (action.type) {
    case 'SET_USER':
      return { ...state, user: action.payload };
    case 'TOGGLE_THEME':
      return { ...state, theme: state.theme === 'light' ? 'dark' : 'light' };
    default:
      return state;
  }
}

// 2. 创建 Context
const StateContext = createContext(null);
const DispatchContext = createContext(null);

// 3. 封装 Provider 组件
export function AppProvider({ children }) {
  const [state, dispatch] = useReducer(appReducer, initialState);
  return (
    <StateContext.Provider value={state}>
      <DispatchContext.Provider value={dispatch}>
        {children}
      </DispatchContext.Provider>
    </StateContext.Provider>
  );
}

// 4. 提供自定义 Hook 便于组件消费状态
export function useAppState() {
  return useContext(StateContext);
}
export function useAppDispatch() {
  return useContext(DispatchContext);
}
```

### useSyncExternalStore 同步外部状态

当需要接入不受 React 控制的外部状态源（如浏览器的 `navigator.onLine` 或第三方库）时，为了保证在[[并发模式|并发渲染]]下的状态一致性，应使用 `useSyncExternalStore`：

```javascript
import { useSyncExternalStore } from 'react';

// 订阅函数：外部状态改变时通知 React
function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}

// 获取快照函数：返回当前状态
function getSnapshot() {
  return navigator.onLine;
}

export function NetworkStatus() {
  // 安全地将外部状态同步到 React 组件中
  const isOnline = useSyncExternalStore(subscribe, getSnapshot);

  return (
    <div>
      当前网络状态: {isOnline ? '🟢 在线' : '🔴 离线'}
    </div>
  );
}
```
