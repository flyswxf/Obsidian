# 模型并行 (Model Parallelism)

模型并行是指当单个模型的参数量大到**无法放入单张 GPU 显存**时，将模型切分到多张 GPU 上协同计算的技术。

## 一、核心思想

与数据并行（Data Parallelism，每张卡有一份完整的模型副本，划分数据）不同，模型并行是**划分模型本身**。主要有以下两种主流策略：

1. **流水线并行 (Pipeline Parallelism, PP)**：
   - 按**层（Layers）**进行切分。例如，将模型的前 10 层放在 GPU 0，后 10 层放在 GPU 1。
   - 数据像流水线一样依次穿过不同的 GPU。
   - **问题**：容易产生“气泡”（GPU 空闲等待时间），需要配合微批次（Micro-batching）调度算法（如 GPipe, 1F1B）来提升利用率。

2. **张量并行 (Tensor Parallelism, TP)**：
   - 按**操作的维度（Tensors/Weights）**进行切分。例如，将一个巨大的矩阵乘法切分成多个小的矩阵乘法，分发到不同 GPU 上计算，最后合并结果。
   - **代表实现**：Megatron-LM。
   - **问题**：需要极高带宽的卡间通信（如 NVLink），因此通常限制在单台物理机内使用。

*(注：现代超大模型如 GPT-3 往往同时采用 3D 并行，即 数据并行 + 流水线并行 + 张量并行 结合)*

## 二、PyTorch 使用

原生 PyTorch 实现复杂的张量并行较为困难，通常借助分布式张量框架 `torch.distributed.tensor.parallel` 或是成熟的第三方库（如 DeepSpeed、Megatron）。

以下是一个**极简的流水线并行概念示例**（手动跨设备移动张量）：

```python
import torch
import torch.nn as nn

class PipelineModel(nn.Module):
    def __init__(self):
        super().__init__()
        # 假设有两张卡
        self.device0 = torch.device('cuda:0')
        self.device1 = torch.device('cuda:1')
        
        # 将模型的前半部分放到 GPU 0
        self.layer1 = nn.Sequential(
            nn.Linear(1024, 4096),
            nn.ReLU()
        ).to(self.device0)
        
        # 将模型的后半部分放到 GPU 1
        self.layer2 = nn.Sequential(
            nn.Linear(4096, 1024)
        ).to(self.device1)
        
    def forward(self, x):
        # 1. 数据在 GPU 0 上进行计算
        x = x.to(self.device0)
        out1 = self.layer1(x)
        
        # 2. 将中间结果传输到 GPU 1
        out1_on_dev1 = out1.to(self.device1)
        
        # 3. 在 GPU 1 上完成剩余计算
        out2 = self.layer2(out1_on_dev1)
        return out2

model = PipelineModel()
# 此时数据输入只需送入模型，内部会自动流转
```

## 三、关键要点说明

- **通信开销**：模型并行的核心痛点是卡间通信。流水线并行的通信量较小，但容易资源闲置；张量并行计算效率高，但通信极度频繁。
- **现代替代/补充方案 (ZeRO / FSDP)**：
  - 微软推出的 **ZeRO (Zero Redundancy Optimizer)** 及 PyTorch 的 **FSDP (Fully Sharded Data Parallel)** 提供了另一种思路。
  - 它们依然像数据并行一样工作，但**把模型参数、梯度、优化器状态在多卡之间进行了切片（Sharding）**。
  - 这是目前训练大模型（如 LLaMA）最主流且易用的显存优化技术，它能实现近乎模型并行的显存节省，同时代码侵入性远小于传统的张量并行。
