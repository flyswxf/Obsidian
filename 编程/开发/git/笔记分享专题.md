## 方案一：利用 Git Subtree 分离为独立仓库
若主仓库为私有（Private），或需要严格限制接收方只能访问 `数据库` 目录及其内容，可使用 `git subtree` 将该目录及其历史记录剥离并推送到新的独立仓库中。

- **核心优势**：无需改变当前本地 Obsidian 笔记的目录结构和双链关系，主仓库和分享仓库的提交互不干扰。
- **执行步骤**：
	1. 在 GitHub 上新建一个用于分享的空仓库（如命名为 `Database-Course-Notes`）。
	2. **在本地 Obsidian 根目录下打开终端，添加新仓库作为第二个远程地址：**
		`git remote add share-db https://github.com/你的用户名/Database-Course-Notes.git`
	3. **使用 Subtree 将指定目录推送到新仓库的主分支：**
		`git subtree push --prefix=课程/数据库 share-db main`
	4. 后续每次在本地更新了数据库笔记并 commit 后，再次执行上述 push 命令即可同步给他人。

## 方案三：接收方使用稀疏检出（Sparse-Checkout）
若基于同一主仓库协作，可通过 Git 的稀疏检出特性，让接收方在克隆时仅下载特定目录。

- **操作方式**（由接收方在本地执行）：
  ```bash
  # 1. 仅克隆仓库元数据，不检出任何文件
  git clone --no-checkout https://github.com/flyswxf/Obsidian.git
  cd Obsidian
  
  # 2. 初始化稀疏检出并指定需要拉取的目录
  git sparse-checkout init --cone
  git sparse-checkout set "课程/数据库"
  
  # 3. 检出分支，此时本地只会显示数据库文件夹
  git checkout main
  ```
- **适用场景**：接收方具备基本的 Git 命令行操作能力。

**综合建议**：若仅为单向分享笔记内容，优先采用 **方案二（Git Subtree）**，能够在维持现有知识库物理结构完全不变的前提下，实现精准的权限隔离与内容分发。
