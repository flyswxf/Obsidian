## 基本定义

Skill（技能）是面向 Agent 的一组**可复用、可发现、可执行的专业能力说明**。它把某类任务所需的知识、流程、约束、工具和参考资料封装起来，使 Agent 能够在需要时加载，而不是把所有规则永久放进系统提示词。

可以把 Skill 理解为 Agent 的“能力插件”：

$$Skill = Knowledge + Workflow + Constraints + Resources$$

Skill 不等同于普通 Prompt：

| 对比项 | 普通 Prompt | Skill |
|---|---|---|
| 作用 | 临时指导一次对话 | 持续复用一类任务能力 |
| 结构 | 通常是一段文本 | 通常包含说明、脚本、模板和参考资料 |
| 触发方式 | 用户直接提供 | 根据任务语义自动发现或显式指定 |
| 工程属性 | 难以测试和版本管理 | 可以版本化、评测、审计和迭代 |
| 上下文策略 | 往往一次性全部注入 | 采用按需加载和渐进式披露 |

## Skill 的核心组成

### 1. 元数据

元数据用于帮助系统发现 Skill，至少应说明：

- 名称：简洁、稳定、具有唯一性。
- 描述：明确说明解决什么问题，以及适用和不适用的场景。
- 版本：用于追踪兼容性和变更。
- 依赖：包括工具、运行环境、权限和外部服务。

### 2. 行为说明

行为说明是 Skill 的核心指令，通常包括：

1. 任务目标和输入输出边界。
2. 推荐的执行流程。
3. 必须遵守的安全、格式和权限约束。
4. 异常情况的处理方式。
5. 完成任务前的验证清单。

好的行为说明应当描述**可观察的行为**，例如“修改文件前先读取文件内容”，而不是只写“认真处理”。

### 3. 资源文件

Skill 可以附带以下资源：

- `scripts/`：可重复执行的脚本或命令。
- `references/`：较长的规范、领域知识和 API 文档。
- `assets/`：模板、示例数据和静态资源。
- 测试用例：用于检查输出是否满足要求。

资源应按需读取。核心说明保持短小，详细内容放进独立文件，避免无关内容占用上下文窗口。

### 4. 工具边界

Skill 可以规定工具的调用顺序、参数格式和禁止事项，但不应绕过权限系统。涉及写文件、执行命令、网络请求或外部部署时，应明确：

- 哪些操作可以自动执行；
- 哪些操作需要用户确认；
- 失败后如何恢复；
- 如何记录执行结果。

这部分与 [[工具调用(Action)#完整执行生命周期|工具调用]] 和 [[Harness Engineering/04_工具注册与执行层#工具执行层|工具执行层]] 直接相关。

## Skill 的工作机制

一次典型的 Skill 执行过程如下：

1. **识别**：根据用户意图匹配 Skill 的名称和描述。
2. **加载**：先读取核心说明，再按需读取引用文件、脚本和模板。
3. **规划**：将用户任务映射到 Skill 要求的执行流程。
4. **执行**：调用工具或生成内容。
5. **验证**：运行测试、检查格式、确认副作用。
6. **反馈**：报告完成内容、验证结果和未解决问题。

可抽象为：

$$Input \rightarrow Discover \rightarrow Load \rightarrow Execute \rightarrow Verify \rightarrow Output$$

## Skill 与 Agent 的关系

Agent 是具备感知、推理、记忆和行动能力的运行主体，Skill 是可以被 Agent 选择和调用的专业能力单元。[[Agent概述#核心架构|Agent 的核心架构]]提供通用能力，Skill 则提供特定领域的方法论。

例如：

- Agent 负责理解“审查这次代码变更”。
- 代码审查 Skill 规定审查维度、严重级别、报告格式和验证方法。
- 工具调用层负责读取差异、运行测试和定位文件。

因此，Skill 更接近“领域 SOP + 执行约束”，而不是一个独立的智能体。

## 设计原则

- **单一职责**：一个 Skill 聚焦一类相近任务。
- **清晰触发**：描述中使用可被用户表达的任务关键词。
- **渐进式披露**：先加载最小必要信息，再深入读取资源。
- **可验证**：每个关键步骤都应有检查方法。
- **可恢复**：失败时提供重试、回滚或人工接管路径。
- **最小权限**：只申请完成任务所需的工具和访问范围。
- **可维护**：说明、脚本、模板和测试彼此分离。

## 常见误区

1. 把 Skill 写成冗长的百科全书，导致触发不准和上下文浪费。
2. 只描述目标，不描述步骤、边界和验收标准。
3. 依赖隐含知识，换一个模型或运行环境就无法执行。
4. 让 Skill 直接执行高风险操作，却没有确认点和审计记录。
5. 资源文件很多，但没有说明何时读取、如何选择。
