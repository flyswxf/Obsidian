## 📌 什么是保持函数依赖（Dependency Preservation）？

在数据库规范化过程中，我们经常需要把一个大表（关系）拆分成多个小表（子关系），以消除冗余、避免更新异常、提高一致性。

拆分的原则有很多，比如：

- 保持无损连接性（Lossless-Join）[[无损分解（Lossless Decomposition）的判定]]
    
- 保持函数依赖（Dependency Preservation）
    

其中**保持函数依赖**，就是希望：

> **原来在拆分前表中存在的所有函数依赖，在拆分后的子关系中依然能够被检查和验证，无需在多个子关系之间做笛卡尔积再去验证。**

### 举个例子：

原来有个关系：

```
R(A, B, C)
F = {A → B, B → C}
```

我们拆成两个表：

```
R1(A, B)
R2(B, C)
```

现在：

- A → B 可以在 R1 中检查 ✅
    
- B → C 可以在 R2 中检查 ✅
    
- 所有依赖都能在单独的子关系中检查完，不需要拼回去再查
    

👉 这种就是**保持了函数依赖**。

但如果拆成：

```
R1(A, C)
R2(B, C)
```

- A → B 没法单独在 R1 或 R2 检查了，需要**把两个表拼回去（笛卡尔积）**才能验证  
    👉 这种就是**不保持函数依赖**。
    

---

## 📌 为什么重要？

> 🌱 **测试一个关系内的依赖代价低** 🌱 **测试多个关系（尤其是需要拼接的）代价高**

所以好设计要尽量保证：

- 拆分后依赖还在子关系里能直接检查
    
- 不要为了范式太过追求分解，结果导致依赖验证变得麻烦
    

---

## 📌 计算是否保持函数依赖的算法（Dependency Preservation Test）

我们来看看怎么判断拆分后的子关系是否保持了所有的函数依赖。

### 设定：

- R：原始关系
    
- F：原始关系的依赖集
    
- ρ = {R1, R2, ..., Rn}：分解后的子关系集合
    

### 算法步骤：

1. **对每个子关系 Ri，计算它上的依赖集**  
    Fᵢ = 投影到 Ri 上的函数依赖（F在Ri上的投影）
    
2. **将所有子关系的依赖集合并**  
    F' = F₁ ∪ F₂ ∪ ... ∪ Fₙ
    
3. **计算 F' 的闭包**  
    F'+ [[函数依赖集#二、函数依赖集的闭包（Closure of FDs Set）]]
    
4. **判断是否等于原来的 F+**
    
    - 如果 F'+ 包含 F+（也就是所有原依赖都能推导出来）👉 保持依赖
        
    - 否则 👉 不保持依赖
        

### 投影依赖怎么求？

把 F 中**涉及子关系 Ri 中属性**的依赖保留，丢掉其他。

例如： F = {A → B, B → C, C → D}  
Ri(A, B, C)  
→ 投影到 Ri 上就是 {A → B, B → C}

---

## 📌 小结一下：

|概念|说明|
|:--|:--|
|**保持函数依赖**|拆分后，原来的依赖还能在子表中直接验证|
|**重要性**|避免高代价的笛卡尔积，保持验证高效|
|**计算方法**|投影→合并→求闭包→对比原闭包|
