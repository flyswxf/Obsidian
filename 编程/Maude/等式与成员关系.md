- **可执行等式**：右侧出现的任何变量都必须在左侧出现
- **不可执行等式**：不满足上述条件的等式需要 `nonexec` 属性

### 1.3 等式的三种指定方式 #不知道有什么用

| 方式 | 描述 | 用途 | 执行方式 |
|------|------|------|----------|
| **标准等式** | 默认方式 | 作为简化规则 | 从左到右执行 |
| **nonexec 等式** | 带 `nonexec` 属性 | 文档化引理 | 不用于简化 |
| **等式属性** | 操作符属性 | 声明代数性质 | 模运算简化 |

### 1.4 示例：NUMBERS 模块
```maude
fmod NUMBERS is
  sorts Zero Nat .
  subsort Zero < Nat .
  
  op zero : -> Zero .
  op s_ : Nat -> Nat .
  op _+_ : Nat Nat -> Nat .
  
  vars N M : Nat .
  eq N + zero = N .
  eq N + s M = s (N + M) .
endfm
```

### 1.5 示例：对称差运算
```maude
op sd : Nat Nat -> Nat .

vars N M : Nat .
eq sd(N, N) = zero .
eq sd(N, zero) = N .
eq sd(zero, N) = N .
eq sd(s N, s M) = sd(N, M) .
```

### 1.6 等式属性 vs 显式等式

**错误做法**：将等式属性写成显式等式
```maude
op f : Nat Nat -> Nat [comm] .
eq f(X, Y) = f(Y, X) .  // 错误：会导致无限循环
```

**正确做法**：仅使用等式属性
```maude
op f : Nat Nat -> Nat [comm] .  // 正确：模运算处理
```

**循环问题**：
```
f(a, b) = f(b, a) = f(a, b) = f(b, a) = ...  // 无限循环
```

## 2. 条件等式与成员关系 (Conditional Equations and Memberships)

### 2.1 基本语法

**条件等式**：
```maude
ceq Term-1 = Term-2 
if EqCondition-1 /\ ... /\ EqCondition-k 
[StatementAttributes] .
```

**条件成员关系**：
```maude
cmb Term : Sort 
if EqCondition-1 /\ ... /\ EqCondition-k 
[StatementAttributes] .
```

### 2.2 条件的组成
条件由以下元素构成：
- **单个等式**：`t = t'`
- **单个成员关系**：`t : s`
- **合取连接**：使用 `/\` 连接多个条件（结合性）

### 2.3 条件中等式的三种变体

| 等式类型 | 语法 | 用途 | 说明 |
|---------|------|------|------|
| **普通等式** | `t = t'` | 标准相等判断 | 双向化简比较 |
| **匹配等式** | `t := t'` | 模式匹配 | 单向匹配绑定 |
| **布尔等式** | `t` | 布尔条件 | 等价于 `t = true` |

### 2.4 布尔等式详解


**等价的完整形式**：
```maude
(N == zero) = true
(M =/= s zero) = true
not (K :: NzNat) = true
(N > zero or M =/= s zero) = true
```

### 2.5 实际应用示例

#### 2.5.1 路径连接的条件成员关系
```maude
var E : Edge .
vars P Q R S : Path .

cmb E ; P : Path if target(E) = source(P) .
```
**解释**：边与路径的连接只有在边的目标节点等于路径的源节点时才构成有效路径

#### 2.5.2 路径连接的结合性
```maude
ceq (P ; Q) ; R = P ; (Q ; R) 
if target(P) = source(Q) /\ target(Q) = source(R) .
```
**解释**：路径连接的结合性需要满足连接条件

#### 2.5.3 使用匹配等式定义操作
```maude
ceq source(P) = source(E) if E ; S := P .
ceq target(P) = target(S) if E ; S := P .
```
**解释**：通过匹配等式 `E ; S := P` 将路径 P 分解为边 E 和路径 S

### 2.6 匹配等式的特殊性质

#### 2.6.1 模式要求
- 匹配等式中的项必须是 **M-模式**
- M-模式：对任何良构替换，如果变量域中每个变量都是规范形式，则整个项也是规范形式
- **充分条件**：项的非变量子项与模块中等式左侧没有合一子

#### 2.6.2 操作语义
- **普通等式**：双向化简后比较相等性（模等式属性）
- **匹配等式**：单向模式匹配，绑定新变量
- **布尔等式**：普通等式的特殊情况

### 2.7 条件求解策略
- **顺序处理**：从左到右依次尝试满足条件
- **多重匹配**：模等式属性的匹配可能产生多个解
- **回溯搜索**：尝试所有可能的匹配直到找到满足条件的解

### 2.8 匹配等式的应用场景

#### 2.8.1 局部变量绑定
类似函数式编程语言中的 `let` 绑定：
```maude
ceq complexOperation(P) = result 
if E ; S := P /\ someCondition(E, S) .
```

#### 2.8.2 结构搜索
无需显式定义搜索函数，直接通过模式匹配进行结构遍历：

**示例：判断数字是否出现在序列内部**
```maude
op _occurs-inner_ : [Nat] [NatSeq] -> [Bool] .
ceq N:Nat occurs-inner NS:NatSeq = true 
if (NS0:NatSeq N:Nat NS1:NatSeq) := NS:NatSeq .
```

**等价的直接形式**：
```maude
eq N:Nat occurs-inner NS0:NatSeq N:Nat NS1:NatSeq = true .
```

**测试结果**：
- `zero occurs-inner (zero zero zero zero zero)` → `true`
- `zero occurs-inner (zero zero)` → 不进一步化简（因为序列长度不足3）

**注意事项**：
- 操作符在 kind 级别定义（部分布尔函数）
- 可使用 `owise` 属性扩展为全函数
- 需考虑结合性和单位元属性的影响

### 2.9 匹配等式的陷阱与注意事项

#### 2.9.1 多重匹配的问题
当M-模式存在多个匹配时，可能导致不一致的结果：

**有问题的示例**：
```maude
op hasTwo : [NatSeq] -> [Bool] .
ceq hasTwo(NS:NatSeq) = N:Nat == s s zero 
if NS0:NatSeq N:Nat NS1:NatSeq := NS:NatSeq .
```

**问题分析**：
- `hasTwo(zero zero)` → 不化简（序列长度不足3）
- `hasTwo(zero (s s zero) zero)` → `true`
- `hasTwo(zero (s zero) (s s zero) zero)` → 可能返回 `true` 或 `false`

#### 2.9.2 语义一致性问题
- **多重匹配**：同一条件等式可能有多个不同的匹配结果
- **Church-Rosser性质失效**：破坏了等式理论的一致性
- **语义混乱**：可能导致 `true` 和 `false` 被等同，产生不一致理论

#### 2.9.3 解决方案
- **规则模块**：在系统模块中使用规则而非等式进行搜索
- **唯一性保证**：确保匹配等式的结果唯一
- **谨慎设计**：避免可能产生多重匹配的模式

## 3. 无条件成员关系 (Unconditional Memberships)

### 3.1 基本语法
```maude
mb Term : Sort [StatementAttributes] .
```

**语法要求**：
- 使用关键字 `mb`
- 项和 sort 必须在同一个 kind 中
- 可选的语句属性用方括号包围

### 3.2 作用
- **类型指定**：将特定项指定为给定 sort 的成员
- **子类型细化**：在 subsort 层次结构中进一步细化类型

### 3.3 示例：3*NAT 模块
```maude
fmod 3*NAT is
  sorts Zero Nat 3*Nat .
  subsorts Zero < 3*Nat < Nat .
  
  op zero : -> Zero .
  op s_ : Nat -> Nat .
  
  var M3 : 3*Nat .
  mb (s s s M3) : 3*Nat .  // 3的倍数仍是3的倍数
endfm
```

**解释**：
- `3*Nat` 表示3的倍数
- `subsorts Zero < 3*Nat < Nat` 建立层次关系
- `mb (s s s M3) : 3*Nat` 确保3的倍数加3仍是3的倍数

### 3.4 与特殊属性的交互
成员关系公理可能与以下属性的操作符产生不良交互：
- `assoc` 属性（结合性）
- `iter` 属性（迭代性）

详见手册第14.2.8和14.2.9节。

## 4. 函数模块的数学语义

### 4.1 等式理论的构成
函数模块定义了一个**成员等式逻辑**中的等式理论，可表示为三元组 `(Σ, E ∪ A)`：

- **Σ (签名)**：模块中所有 sort、subsort、kind 和操作符的规范
- **E (等式集合)**：所有语句（等式和成员关系，可能是条件的）
- **A (等式属性)**：操作符的特殊属性（如 `assoc`、`comm` 等）

### 4.2 代数模型

#### 4.2.1 项代数 T_Σ
- **定义**：由签名 Σ 语法定义的基项族
- **特性**：语法不同的项表示不同元素
- **问题**：不满足 E ∪ A 中的等式（除非是平凡等式如 `f(X) = f(X)`）

#### 4.2.2 初始代数 T_Σ,E∪A
- **无垃圾性质**：所有元素都可由基项表示
- **无混淆性质**：只有被公理 E ∪ A 强制相等的元素才被等同
- **数学构造**：T_Σ 的商代数，等价类为可证明相等的项

#### 4.2.3 规范项代数 Can_Σ,E∪A
在 E 是 Church-Rosser 且终止的（模 A）条件下：
```
T_Σ,E∪A ≅ Can_Σ,E∪A
```
- **规范形式**：不能被 E 中等式进一步化简的项（模 A）
- **计算语义**：Maude 解释器计算的规范形式即为函数表达式的值

### 4.3 Maude 的计算模型
- **reduce 命令**：计算项的规范形式
- **函数式语义**：规范形式作为函数表达式的值
- **模属性化简**：考虑等式属性的化简过程

## 5. 与函数模块的关联

本内容是 [[模块 Modules#3.1 函数模块 (Functional Modules)]] 的核心组成部分：

- **等式**：定义函数的计算规则

## 6. 最佳实践

### 6.1 等式设计
- 确保可执行等式满足变量条件
- 避免将等式属性写成显式等式
- 保证简化规则的终止性和Church-Rosser性质

### 6.2 成员关系设计
- 合理使用 subsort 层次结构
- 注意与特殊属性操作符的交互
### 6.3 条件等式设计
- **避免多重匹配**：确保匹配等式结果的唯一性
- **保持一致性**：避免破坏 Church-Rosser 性质
- **合理使用匹配等式**：优先考虑在系统模块中使用规则进行搜索
- **M-模式验证**：确保匹配模式满足 M-模式要求
