## IPv4 协议基础

IP (Internet Protocol) 是网络层的核心协议，负责将数据报从源主机无连接地传输到目的主机。

### IPv4 数据报首部结构

一个标准的 IPv4 报文首部通常为 20 字节（不包含选项字段）。其结构如下：

![[assets/ipv4_header.svg]]

- **版本 (Version)**：4 位，指明 IP 协议版本（IPv4 为 4）。
- **首部长度 (IHL)**：4 位，以 32 位（4 字节）为单位。最小为 5（即 20 字节）。
- **总长度 (Total Length)**：16 位，指明整个 IP 数据报的长度，最大为 65535 字节。
- **标识 (Identification)、标志 (Flags)、片偏移 (Fragment Offset)**：这三个字段共同用于数据报的分片与重组。当数据报大小超过链路的 MTU 时，必须进行分片。
- **生存时间 (TTL, Time to Live)**：8 位，防止数据报在网络中无限循环。每经过一个路由器，TTL 减 1，减为 0 时数据报被丢弃并发送 ICMP 报文。
- **协议 (Protocol)**：8 位，指示数据负载应交给哪个上层协议（如 TCP 为 6，UDP 为 17）。
- **源地址与目的地址**：各 32 位，用于标识通信双方。

### IPv4 编址与 NAT

IPv4 地址长度为 32 位，早期分为 A、B、C、D、E 五类。为了解决 IP 地址枯竭问题，引入了：
- **CIDR (无类别域间路由)**：消除了传统的 A/B/C 类地址划分，使用子网掩码（如 `/24`）来灵活划分网络号和主机号。
- **NAT (网络地址转换)**：允许多个内部主机共享一个或少数几个公网 IP 地址与外部通信，极大缓解了 IPv4 地址短缺。

## IPv6 协议

随着互联网规模的爆炸式增长，IPv4 地址空间最终耗尽。IPv6 被提出作为下一代互联网协议。

- **巨大的地址空间**：IPv6 地址长度为 128 位，理论上可以为地球上的每一粒沙子分配一个 IP 地址。
- **简化的首部**：IPv6 取消了首部校验和、分片字段（分片由源主机完成，路由器不再分片）以及选项字段（改为扩展首部），使得路由器的处理速度更快。
- **原生支持安全性**：IPsec 成为 IPv6 的标准配置。
