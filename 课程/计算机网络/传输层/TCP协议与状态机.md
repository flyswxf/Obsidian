## TCP 协议原理

传输控制协议 (TCP, Transmission Control Protocol) 是一个面向连接的、可靠的、基于字节流的传输层协议。它通过序列号、确认应答、重传机制、校验和等技术，在不可靠的 IP 网络之上提供了一条可靠的端到端字节流通道。

## TCP 连接管理与状态机

TCP 是一种有状态的协议，连接的建立、数据传输和断开都需要经历严格的状态转换。

### 三次握手建立连接
为了建立连接，客户端和服务器需要进行三次握手 (Three-way Handshake)：
1. **SYN**：客户端发送一个 SYN（同步序列编号）报文段，进入 `SYN_SENT` 状态。
2. **SYN + ACK**：服务器收到 SYN 后，返回一个 SYN + ACK 报文段，进入 `SYN_RCVD` 状态。
3. **ACK**：客户端收到服务器的 SYN+ACK 后，发送一个 ACK 报文段。此时客户端进入 `ESTABLISHED` 状态。服务器收到该 ACK 后，也进入 `ESTABLISHED` 状态，连接正式建立。

### 四次挥手释放连接
连接的释放需要四次挥手 (Four-way Wavehand)：
1. **FIN**：主动关闭方（通常是客户端）发送一个 FIN 报文段，进入 `FIN_WAIT_1` 状态。
2. **ACK**：被动关闭方收到 FIN，返回一个 ACK，进入 `CLOSE_WAIT` 状态。主动关闭方收到该 ACK 后进入 `FIN_WAIT_2` 状态。此时连接处于半关闭状态，被动关闭方仍可发送数据。
3. **FIN**：被动关闭方的数据发送完毕后，发送一个 FIN 报文段，进入 `LAST_ACK` 状态。
4. **ACK**：主动关闭方收到 FIN，返回一个 ACK，进入 `TIME_WAIT` 状态。被动关闭方收到 ACK 后进入 `CLOSED` 状态。

### TIME_WAIT 状态的作用
主动关闭方在发送完最后一个 ACK 后，必须在 `TIME_WAIT` 状态等待 2MSL (Maximum Segment Lifetime，报文最大生存时间)。其主要目的是：
- 确保最后一个 ACK 能够可靠到达被动关闭方。如果 ACK 丢失，被动关闭方会重传 FIN，主动关闭方可以在这段时间内重新发送 ACK。
- 防止“已失效的连接请求报文段”出现在本连接中。等待 2MSL 可以使得本连接持续的时间内所产生的所有报文段都从网络中消失。

## TCP 流量控制

TCP 使用基于[[数据链路层/滑动窗口协议|滑动窗口机制]]的流量控制。接收方在返回的 TCP 头部中会包含一个“窗口大小”字段，告知发送方目前自己接收缓存的剩余可用空间。发送方根据这个窗口大小来动态调整发送数据的速率，从而防止发送速度过快导致接收方缓存溢出。
