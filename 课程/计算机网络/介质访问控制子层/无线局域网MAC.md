## 无线环境下的特殊问题

与有线局域网相比，无线局域网 (WLAN, IEEE 802.11) 的介质访问控制面临着两个独特的物理挑战：
1. **隐藏终端问题 (Hidden Terminal Problem)**：节点 A 和 C 都可以与中间的节点 B 通信，但 A 和 C 相互之间由于距离过远或障碍物阻挡而无法感知对方。当 A 和 C 同时向 B 发送数据时，它们无法在发送前监听到对方的信号，从而在 B 处引发冲突。
2. **暴露终端问题 (Exposed Terminal Problem)**：节点 B 在向 A 发送数据，此时节点 C 想要向节点 D 发送数据。C 监听信道发现信道忙（听到了 B 的信号），因此推迟发送。但实际上，C 向 D 的发送并不会干扰 B 向 A 的发送，这种保守的退避降低了信道利用率。

此外，无线电收发器通常无法做到同时发送和接收信号（即无法像有线网络那样一边发送一边进行冲突检测）。因此，[[CSMA_CD与以太网#CSMA/CD 协议|CSMA/CD 协议]]不适用于无线局域网。

## CSMA/CA 协议

为了解决上述问题，IEEE 802.11 采用了 CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance，带有冲突避免的载波监听多路访问) 协议。

### 冲突避免机制
- 在发送数据前，节点不仅要监听信道，还要在信道空闲后等待一个帧间间隔 (IFS)。
- 采用随机退避机制，以降低多个节点同时发送的概率。
- 引入了确认 (ACK) 机制。由于无法在发送中检测冲突，发送方只有在收到接收方返回的 ACK 后，才认为帧发送成功。如果超时未收到 ACK，则认为发生了冲突或数据丢失，从而进行重传。

### RTS/CTS 握手机制
为了有效解决隐藏终端问题，802.11 标准引入了可选的 RTS/CTS 机制：
1. **RTS (Request to Send)**：发送方在发送数据前，先向接收方发送一个短小的 RTS 控制帧，其中包含了后续数据传输所需的持续时间。
2. **CTS (Clear to Send)**：接收方收到 RTS 后，如果准备好接收，则广播一个 CTS 帧，同样包含传输持续时间。
3. 周围的节点（无论是发送方的邻居还是接收方的邻居）在听到 RTS 或 CTS 后，会将其内部的网络分配矢量 (NAV, Network Allocation Vector) 设置为该持续时间，在这段时间内保持静默。

这种虚拟载波监听技术极大地减少了数据帧冲突的概率。
