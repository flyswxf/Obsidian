## 电子邮件系统架构

电子邮件系统是互联网上最古老也最常用的应用之一。它的架构主要由用户代理、邮件服务器和邮件传输协议组成。

1. **用户代理 (User Agent)**：用户与电子邮件系统的接口（如 Outlook、Apple Mail 或 Web 邮箱界面），负责邮件的撰写、阅读和管理。
2. **邮件服务器 (Mail Server)**：负责接收、路由和投递邮件。每个用户的邮箱都托管在某个邮件服务器上。

### 核心邮件协议

电子邮件的发送和接收使用了不同的协议，它们都依赖于[[传输层/TCP协议与状态机|TCP 协议]]以确保邮件不丢失。

- **SMTP (Simple Mail Transfer Protocol)**：简单邮件传输协议，用于将邮件从发送方的用户代理推送到发送方邮件服务器，以及在邮件服务器之间中继邮件。SMTP 是一种“推 (Push)”协议。
- **POP3 (Post Office Protocol version 3)**：邮局协议，用于用户代理从邮件服务器拉取邮件。POP3 通常将邮件下载到本地后从服务器上删除（虽然可以配置为保留）。
- **IMAP (Internet Message Access Protocol)**：比 POP3 更高级的“拉 (Pull)”协议。它允许用户在服务器上管理文件夹、标记邮件状态，且多设备之间可以保持同步。

在寻址目标邮件服务器时，发送方邮件服务器需要查询目标域名的 [[DNS域名系统#DNS 记录类型|MX 记录]] 以获取正确的 IP 地址。

## 流媒体与多媒体网络

随着网络带宽的提升，音视频流媒体成为网络流量的主力。多媒体应用对延迟、抖动（Jitter）高度敏感，但对偶尔的数据丢失有一定的容忍度。

### 流媒体传输协议

- **UDP 优先**：早期的实时流媒体传输倾向于使用 [[传输层/UDP协议原理|UDP]]，因为重传丢失的 TCP 数据包会导致无法忍受的播放延迟。
- **RTP/RTCP**：实时传输协议 (RTP) 运行在 UDP 之上，为多媒体数据提供时间戳和序列号，帮助接收端同步和排序。RTCP 用于提供传输质量的反馈。

### 基于 HTTP 的自适应流媒体 (DASH)

现代流媒体（如 YouTube、Netflix）逐渐放弃了纯 UDP 方案，转向了 **DASH (Dynamic Adaptive Streaming over HTTP)**：
1. 视频被编码为多个不同的分辨率和比特率版本。
2. 每个版本被切割成几秒钟长的短片段。
3. 客户端通过 HTTP 下载一个清单文件 (Manifest)，了解所有可用的片段。
4. 客户端在播放过程中，根据当前网络的实际可用带宽和本地缓冲区的大小，动态选择请求哪个清晰度的片段。

这种方案穿透防火墙能力强（因为使用了标准的 HTTP 端口 80/443），且充分利用了现有的内容分发网络 (CDN) 基础设施。
