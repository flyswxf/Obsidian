## DNS 的作用

在网络层，主机之间的通信依赖于[[网络层/IPv4与IPv6协议|IP 地址]]。然而，人类难以记忆纯数字的 IP 地址。域名系统 (DNS, Domain Name System) 的主要任务是将人类可读的域名（如 `www.google.com`）转换为机器可读的 IP 地址。

DNS 是一个分布式的、层次化的数据库系统，运行在应用层，通常底层基于[[传输层/UDP协议原理|UDP 协议]]（端口 53）进行查询，以降低延迟。

## 域名空间层级

DNS 采用树状结构的命名空间：
1. **根域 (Root)**：用点 `.` 表示，是域名树的顶端。全球有 13 组根域名服务器。
2. **顶级域 (TLD, Top-Level Domain)**：如 `.com`, `.org`, `.net`, `.cn` 等。
3. **二级域 (Second-Level Domain)**：如 `google.com`, `baidu.com`。
4. **子域与主机名**：如 `www.google.com` 中的 `www`。

## DNS 查询过程

当用户在浏览器中输入域名时，DNS 解析通常经历以下步骤：

### 1. 本地缓存查找
操作系统首先检查本地 DNS 缓存（如 hosts 文件或系统的 DNS 解析器缓存）。如果命中，则直接返回 IP 地址。

### 2. 向本地域名服务器发起请求
如果本地没有缓存，主机会向其配置的本地域名服务器 (Local DNS Server) 发起递归查询 (Recursive Query)。这意味着本地域名服务器必须代为寻找最终的 IP 地址。

### 3. 迭代查询 (Iterative Query)
本地域名服务器代表客户端，向各级服务器进行迭代查询：
- 首先，向**根域名服务器**查询，根服务器返回负责该顶级域（如 `.com`）的 TLD 服务器的 IP 地址。
- 接着，向 **TLD 域名服务器**查询，TLD 服务器返回负责该二级域（如 `google.com`）的权威域名服务器的 IP 地址。
- 最后，向**权威域名服务器** (Authoritative DNS Server)查询，权威服务器返回该域名对应的最终 IP 地址。

### 4. 返回结果与缓存
本地域名服务器将解析结果返回给客户端，并将其缓存在本地，以便加速后续的相同查询。

## DNS 记录类型

DNS 数据库中包含不同类型的资源记录 (RR, Resource Record)：
- **A 记录**：将主机名映射到 IPv4 地址。
- **AAAA 记录**：将主机名映射到 IPv6 地址。
- **CNAME 记录**：规范名称记录，用于将一个域名指向另一个域名（别名）。
- **MX 记录**：邮件交换记录，用于定位负责接收该域[[电子邮件与流媒体#电子邮件系统架构|电子邮件]]的邮件服务器。
- **NS 记录**：指定该域名的权威域名服务器。
