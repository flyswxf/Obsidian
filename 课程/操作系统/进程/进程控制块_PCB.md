## 进程控制块 (PCB)

在操作系统中，每个进程都由一个进程控制块（Process Control Block, PCB，也称为任务控制块）来表示。PCB 充当了进程特定信息的存储库，包含了管理进程所需的所有数据。

### PCB 的组成信息

PCB 通常包含以下几类核心信息：
- **进程状态**：记录进程当前所处的状态，如新建、就绪、运行、等待或终止（详情参见[[进程概念与状态#进程状态|进程状态]]）。
- **程序计数器（Program Counter）**：指示进程要执行的下一条指令的地址。
- **CPU 寄存器**：包括累加器、索引寄存器、堆栈指针和通用寄存器等。在发生中断时，必须保存这些状态信息，以便之后能正确恢复进程的执行。
- **CPU 调度信息**：包含进程优先级、调度队列指针以及其他调度参数。
- **内存管理信息**：根据操作系统使用的内存系统，这些信息可能包括基址和界限寄存器的值、页表或段表。
- **记账信息**：包括 CPU 使用时间、实际使用时间、时间限制、账号编号、作业或进程编号等。
- **I/O 状态信息**：包含分配给进程的 I/O 设备列表、打开的文件列表等。

## 上下文切换

当 CPU 切换到另一个进程时，系统必须保存旧进程的状态并加载新进程的保存状态，这一过程称为上下文切换（Context Switch）。

上下文切换的具体流程如下：
1. 正在运行的进程由于中断或系统调用而失去 CPU 控制权。
2. 操作系统暂停该进程的执行，并将其当前的上下文（包括程序计数器和 CPU 寄存器等）保存到该进程的 PCB 中。
3. 操作系统将该进程的 PCB 移动到适当的队列（如就绪队列或 I/O 等待队列）中。
4. 调度程序选择另一个处于就绪状态的进程。
5. 操作系统从所选进程的 PCB 中恢复其上下文，更新硬件寄存器。
6. 将 CPU 控制权转移给新选择的进程，开始执行其下一条指令。

上下文切换时间是纯粹的系统开销，因为在切换期间系统不执行任何有用的工作。切换时间的长短高度依赖于硬件支持和内存速度。如果在上下文切换中存在多级缓存的刷新，则性能下降 $P$ 可以用公式 $P = \alpha \cdot t_{flush} + \beta \cdot t_{miss}$ 描述，其中 $t_{flush}$ 表示刷新缓存的时间。
