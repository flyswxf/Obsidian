## 银行家算法概述
为了避免系统进入[[死锁特征与处理方法|死锁状态]]，操作系统可以采用死锁避免策略。银行家算法（Banker's Algorithm）是一种经典的死锁避免算法。其核心思想是：当新进程进入系统时，必须声明其可能需要的每种资源类型的最大实例数。当进程请求资源时，系统会检查此次分配是否会使系统处于**安全状态**。如果安全，则分配资源；否则，进程必须等待。

## 数据结构
银行家算法需要维护以下数据结构，假设 $n$ 为系统中进程的数量，$m$ 为资源类型的数量：

- `Available`：长度为 $m$ 的向量，表示每种资源类型的可用实例数。
- `Max`：$n \times m$ 的矩阵，定义每个进程对每种资源的最大需求。
- `Allocation`：$n \times m$ 的矩阵，定义当前分配给每个进程的每种资源数量。
- `Need`：$n \times m$ 的矩阵，表示每个进程还需要多少资源才能完成任务。关系如下：
  $$ Need[i, j] = Max[i, j] - Allocation[i, j] $$

## 算法核心逻辑

### 安全性算法
用于确定系统是否处于安全状态：
1. 初始化两个向量 `Work` 和 `Finish`：
   - `Work = Available`
   - 对所有 $i = 0, 1, \dots, n-1$，`Finish[i] = false`
2. 查找满足以下条件的索引 $i$：
   - `Finish[i] == false`
   - $Need_i \le Work$ （即进程 $P_i$ 的资源需求可以被当前可用资源满足）
   如果不存在这样的 $i$，跳转到步骤 4。
3. 假设进程 $P_i$ 获得资源并执行完毕释放资源：
   - `Work = Work + Allocation_i`
   - `Finish[i] = true`
   - 跳转到步骤 2。
4. 如果对所有 $i$，都有 `Finish[i] == true`，则系统处于安全状态；否则系统处于不安全状态。

### 资源请求算法
当进程 $P_i$ 提出资源请求 $Request_i$ 时：
1. 如果 $Request_i \le Need_i$，转到步骤 2；否则产生错误（请求超过最大声明）。
2. 如果 $Request_i \le Available$，转到步骤 3；否则 $P_i$ 必须等待。
3. 假定系统将资源分配给 $P_i$，并修改状态：
   - `Available = Available - Request_i`
   - `Allocation_i = Allocation_i + Request_i`
   - `Need_i = Need_i - Request_i`
4. 调用安全性算法。如果系统安全，则真正分配资源；如果不安全，则恢复原状态，$P_i$ 等待。

## 实例推导步骤
假设系统中有 5 个进程 $\{P_0, P_1, P_2, P_3, P_4\}$ 和 3 种资源 $\{A, B, C\}$。资源实例总数分别为 A=10, B=5, C=7。

在时刻 $T_0$，系统的状态如下：

| 进程 | Allocation (A B C) | Max (A B C) | Need (A B C) | Available (A B C) |
|------|--------------------|-------------|--------------|-------------------|
| $P_0$| 0 1 0              | 7 5 3       | 7 4 3        | 3 3 2             |
| $P_1$| 2 0 0              | 3 2 2       | 1 2 2        |                   |
| $P_2$| 3 0 2              | 9 0 2       | 6 0 0        |                   |
| $P_3$| 2 1 1              | 2 2 2       | 0 1 1        |                   |
| $P_4$| 0 0 2              | 4 3 3       | 4 3 1        |                   |

**推导当前系统是否安全：**
1. 初始 `Work = [3, 3, 2]`。
2. 寻找 $Need_i \le Work$ 的进程。
   - $P_1$ 的 $Need = [1, 2, 2] \le [3, 3, 2]$。满足。
   - 假设 $P_1$ 执行完毕，释放其资源：`Work = Work + Allocation_1 = [3, 3, 2] + [2, 0, 0] = [5, 3, 2]`。标记 $P_1$ 完成。
3. 继续寻找：
   - $P_3$ 的 $Need = [0, 1, 1] \le [5, 3, 2]$。满足。
   - 释放资源：`Work = [5, 3, 2] + [2, 1, 1] = [7, 4, 3]`。标记 $P_3$ 完成。
4. 继续寻找：
   - $P_4$ 的 $Need = [4, 3, 1] \le [7, 4, 3]$。满足。
   - 释放资源：`Work = [7, 4, 3] + [0, 0, 2] = [7, 4, 5]`。标记 $P_4$ 完成。
5. 继续寻找：
   - $P_0$ 的 $Need = [7, 4, 3] \le [7, 4, 5]$。满足。
   - 释放资源：`Work = [7, 4, 5] + [0, 1, 0] = [7, 5, 5]`。标记 $P_0$ 完成。
6. 继续寻找：
   - $P_2$ 的 $Need = [6, 0, 0] \le [7, 5, 5]$。满足。
   - 释放资源：`Work = [7, 5, 5] + [3, 0, 2] = [10, 5, 7]`。标记 $P_2$ 完成。

所有进程都能完成，存在安全序列 $<P_1, P_3, P_4, P_0, P_2>$，因此当前系统处于**安全状态**。
