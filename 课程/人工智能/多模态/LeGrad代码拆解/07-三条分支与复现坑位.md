## 1. 三条分支的判定

```python
# wrapper.py L36-72
if isinstance(self.visual, VisionTransformer):
    if self.visual.attn_pool is None:
        self.model_type = 'clip'          # 标准 CLIP：用 [CLS] 聚合
    else:
        self.model_type = 'coca'          # CoCa：用 AttentionalPooler 聚合
elif isinstance(self.visual, TimmModel):
    self.model_type = 'timm_siglip'       # SigLIP：timm 实现 + AttentionPoolHead
else:
    raise ValueError("Model currently not supported")
```

对应三套 hook：

| `model_type` | 装的 hook | 求梯度的对象 |
| --- | --- | --- |
| `clip` | `hooked_torch_multi_head_attention_forward` + `hooked_resblock_forward` | 每层**自注意力**图 |
| `coca` | `hooked_resblock_forward` + `attn_pool.attn.forward` 的 hook | **池化注意力**图 |
| `timm_siglip` | `hooked_resblock_timm_forward` + `hooked_attentional_pooler_timm_forward` | **池化注意力**图 |

注意 CoCa 分支**不给每层自注意力装 hook**（`_activate_att_pool_hooks` 只替换了 `resblocks[l].forward`，没替换 `attn.forward`），因为它只关心池化注意力。

## 2. 总对比表

| | `compute_legrad_clip` | `compute_legrad_coca` | `compute_legrad_siglip` |
| --- | --- | --- | --- |
| 图像复制 $P$ 份 | **是** `image.repeat(P,1,1,1)` | 否 | 否 |
| 张量布局 | LND $(T,P,d)$ | LND → `permute` 成 $(P,T,d)$ | NLC $(P,T,C)$ |
| $s^l$ 怎么算 | token 平均 + `ln_post` + `@proj` | 每层重跑 `attn_pool`，取第 0 个 query，`@proj` | 每层重跑 timm `attn_pool` |
| 求梯度的对象形状 | $(P{\cdot}h, T, T)$ | $(h, 256, T)$ | $(P, h, 1, T)$ |
| 取分数的写法 | `sum(one_hot * sim)` **取对角** | `torch.sum(sim)` **全加** | `torch.sum(sim)` **全加** |
| 聚合下标 | `.mean(1).mean(1)[:, 1:]` | `.mean(0)[0, 1:]` | `.mean(1)[:, 0]` |
| 丢 `[CLS]` | 丢**列**（key） | 丢**列**（key） | 不丢（SigLIP 无 `[CLS]`）；`[:, 0]` 是选唯一的 query **行** |
| 插值时机 | 每层插值后累加 | 每层插值后累加 | 累加完再插值一次 |
| 归一化 | `min_max`（逐 prompt） | 手写全局 min-max | `min_max`（逐样本） |
| 空提示校正 | 无 | 无 | **有**，阈值 0.8 |
| 输出形状 | $(1, P, H, W)$ | $(1, 1, H, W)$ | $(B, 1, H, W)$ |
| 逐 prompt 出图？ | **能** | **不能** | **不能** |

## 3. CoCa 分支

```python
def compute_legrad_coca(self, text_embedding, image=None):
    if image is not None:
        _ = self.encode_image(image)              # ← 没有 repeat，batch 就是传进来时的样子

    for layer in range(self.starting_depth, len(self.visual.transformer.resblocks)):
        intermediate_feat = self.visual.transformer.resblocks[layer].feat_post_mlp  # (T, B, d)
        intermediate_feat = intermediate_feat.permute(1, 0, 2)                      # (B, T, d)
        image_features_list.append(intermediate_feat)

    for layer, (blk, img_feat) in enumerate(...):
        image_embedding = self.visual.attn_pool(img_feat)[:, 0]   # (B, 256, d) → (B, d)
        image_embedding = image_embedding @ self.visual.proj
        sim = text_embedding @ image_embedding.transpose(-1, -2)  # (P, B)
        one_hot = torch.sum(sim)                                  # ← 全部加起来
        attn_map = self.visual.attn_pool.attn.attention_maps       # (h, 256, T)
        grad = torch.autograd.grad(one_hot, [attn_map], retain_graph=True, create_graph=True)[0]
        grad = torch.clamp(grad, min=0.)
        image_relevance = grad.mean(dim=0)[0, 1:]                  # 平均 head → 取第 0 个 query → 丢 CLS 列
        expl_map = rearrange(image_relevance, '(w h) -> 1 1 w h', w=w, h=h)
```

三个要点：

1. **`attn_pool` 在循环里被反复调用**。池化头是模型最后才用一次的模块，LeGrad 却把它套在**每一层**的中间特征上，人为造出"第 $l$ 层的池化结果"，这样才能对每层求 $s^l$。每次调用都会覆盖 `attn_pool.attn.attention_maps`，所以必须紧接着取用。
2. **`[:, 0]` 取第 0 个 latent query**。CoCa 的 `AttentionalPooler` 有 256 个可学习 query（`n_queries=256`），但只有第 0 个是拿对比损失训练的，其余用于 caption 生成，所以只保留它。
3. **`torch.sum(sim)` 把所有 prompt 加成一个标量**，输出只有 $(1,1,H,W)$ 一张图。多 prompt 时得到的是"所有 prompt 混在一起"的热图，无法区分。

## 4. SigLIP 分支

```python
def compute_legrad_siglip(self, text_embedding, image=None, apply_correction=True,
                          correction_threshold=0.8):
    blocks_list = list(dict(self.visual.trunk.blocks.named_children()).values())
    if image is not None:
        _ = self.encode_image(image)               # [bs, num_patch, dim]  bs=num_masks

    num_tokens = blocks_list[-1].feat_post_mlp.shape[1]    # ← shape[1]，NLC 布局
    w = h = int(math.sqrt(num_tokens))                     # SigLIP 无 CLS，不用减 1

    if apply_correction:
        self._init_empty_embedding()
        accum_expl_map_empty = 0

    accum_expl_map = 0
    for layer, (blk, img_feat) in enumerate(...):
        self.zero_grad()
        pooled_feat = self.visual.trunk.attn_pool(img_feat)        # (B, C)
        pooled_feat = F.normalize(pooled_feat, dim=-1)
        sim = text_embedding @ pooled_feat.transpose(-1, -2)       # (P, B)
        one_hot = torch.sum(sim)
        grad = torch.autograd.grad(one_hot, [self.visual.trunk.attn_pool.attn_probs],
                                   retain_graph=True, create_graph=True)[0]
        grad = torch.clamp(grad, min=0.)
        image_relevance = grad.mean(dim=1)[:, 0]                   # 平均 head → 取唯一 query 行
        expl_map = rearrange(image_relevance, 'b (w h) -> b 1 w h', w=w, h=h)
        accum_expl_map += expl_map

        if apply_correction:
            sim_empty = pooled_feat @ self.empty_embedding          # 同一张图上再反向一次
            one_hot_empty = torch.sum(sim_empty)
            grad_empty = torch.autograd.grad(one_hot_empty, [self.visual.trunk.attn_pool.attn_probs],
                                             retain_graph=True, create_graph=True)[0]
            grad_empty = torch.clamp(grad_empty, min=0.)
            image_relevance_empty = grad_empty.mean(dim=1)[:, 0]
            accum_expl_map_empty += rearrange(image_relevance_empty, 'b (w h) -> b 1 w h', w=w, h=h)

    if apply_correction:
        heatmap_empty = min_max(accum_expl_map_empty)
        accum_expl_map[heatmap_empty > correction_threshold] = 0    # 背景伪影抹零

    Res = min_max(accum_expl_map)
    Res = F.interpolate(Res, scale_factor=self.patch_size, mode='bilinear')
    return Res
```

### 4.1 空提示校正（原文附录 7.5）

SigLIP 有个已知现象：**不管输入什么图，背景区域都会出现高激活**。原因是池化注意力对某些位置有与输入无关的偏好。

处理办法是"用一个没有语义的 prompt 再算一遍，把它也点亮的地方当成伪影抹掉"：

```python
def _init_empty_embedding(self):
    if not hasattr(self, 'empty_embedding'):
        _tok = open_clip.get_tokenizer(model_name='ViT-B-16-SigLIP')
        empty_text = _tok(['a photo of a']).to(self.logit_scale.data.device)
        empty_embedding = self.encode_text(empty_text)
        empty_embedding = F.normalize(empty_embedding, dim=-1)
        self.empty_embedding = empty_embedding.t()      # (1, d) → (d, 1)，方便右乘
```

`"a photo of a"` 是个话说到一半的空提示，不含任何物体名词。逻辑链条：

1. 对同一张图、同一个池化注意力图，用空提示求一次梯度 → `accum_expl_map_empty`
2. 归一化后，**空提示热图 > 0.8 的位置 = 不需要语义就会亮的地方 = 伪影**
3. 把真实热图上这些位置直接置 0

抹零发生在真实热图 min-max **之前**，所以被抹掉的位置随后成为最小值，图上呈现为最暗。

三个实现细节：

- `retain_graph=True` 在这里有双重必要：既要跨层复用，又要**同一层反向两次**（真实 prompt 一次、空 prompt 一次）
- tokenizer 硬编码成 `'ViT-B-16-SigLIP'`，注释说"目前只支持 SigLIP，它们共用同一个 tokenizer"
- `apply_correction` 默认 `True`，但 `compute_legrad` 只把它传给 SigLIP 分支——CLIP 和 CoCa 分支的函数签名根本不接收这个参数，所以 `repro.py` 的 `--apply-correction` 对它们无效

### 4.2 批量维的用途不同

`# [bs, num_patch, dim] bs=num_masks` 这行注释泄露了设计意图：SigLIP 分支的 batch 维是给**一批扰动图像**用的，不是给一批 prompt 用的。扰动评测（原文表 6）需要按热图相关性逐步遮挡图像、每遮一次算一次分数，正好是"1 个 prompt × $N$ 张遮挡图"的形状。

所以 `torch.sum(sim)` 在这个场景下是对 $N$ 张遮挡图的分数求和，逐张产出热图，语义是自洽的；只是拿它跑"1 张图 × $N$ 个 prompt"就会退化。

## 5. 为什么 CoCa / SigLIP 分支不能逐 prompt 出图

设图像 batch 为 $B$、prompt 数为 $P$，两个分支都执行：

$$s = \sum_{i=1}^{P}\sum_{j=1}^{B} \text{sim}[i,j]$$

对第 $j$ 份图像的池化注意力 $A_j$ 求梯度：

$$\frac{\partial s}{\partial A_j} = \sum_{i=1}^{P}\frac{\partial \text{sim}[i,j]}{\partial A_j}$$

**所有 prompt 的贡献都叠加进了同一张图**。当 $B=1$（单张图）时，$P$ 个 prompt 得到完全相同的热图；当 $B>1$ 时，每张图的热图都是全部 prompt 的混合。

CLIP 分支靠两件事避开了这个问题：

1. `image.repeat(P,1,1,1)` 让 $B = P$，每份副本只配一个 prompt
2. `sum(one_hot * sim)` 只取对角线，$s = \sum_p \text{sim}[p,p]$，于是 $\partial s/\partial A_j = \partial \text{sim}[j,j]/\partial A_j$，各副本互不相干

**要给 CoCa / SigLIP 逐 prompt 出图，只能一个 prompt 调一次函数。**

## 6. 文本嵌入是否归一化的影响

`playground.py` 和 `repro.py` 都用 `encode_text(text, normalize=True)`。这一步对三个分支的影响不同：

- **CLIP 分支：不影响结果。** 把 $\text{text}_p$ 缩放 $c$ 倍，$s_p$ 和 $\nabla A_p$ 同比缩放 $c$，但最后 `min_max` 是逐 prompt 独立做的，$c$ 被约掉
- **CoCa / SigLIP 分支：影响结果。** 因为多个 prompt 的 $s$ 被加在一起，模长大的 prompt 会占更大权重，热图偏向它

### 7.2 只影响性能／显存

| # | 事项 | 位置 | 说明 |
| --- | --- | --- | --- |
| 9 | `create_graph=True` 多余 | `wrapper.py` L174、L219、L267、L280 | 全程没有二阶求导。去掉后梯度张量不挂计算图，逐层累加时不会把 $L$ 份图吊在内存里 |

| 11 | `zero_grad()` 是空操作 | `wrapper.py` L166、L207、L261 | `autograd.grad` 直接返回梯度、不写 `.grad` |
| 12 | `one_hot.requires_grad_(True)` 无作用 | `wrapper.py` L168 | 从没对这个单位阵求过导 |
| 13 | CLIP 分支每层先插值再累加 | `wrapper.py` L181-182 | 与"先累加再插值"数学等价（双线性是线性算子），但在 448 分辨率下每层多占 $P\times448^2$ 的显存 |

**显存量级估算**（float32，仅注意力图本身，不含反向中间量）：

| 输入 | 单份副本单层 | $P=3$、12 层 |
| --- | --- | --- |
| 224（$T=197$） | $12\times197^2\times4 \approx 1.9$ MB | $\approx 67$ MB |
| 448（$T=785$） | $12\times785^2\times4 \approx 29.6$ MB | $\approx 1.06$ GB |

反向传播还要为每个建图的层保存中间量，实际占用约为上表的 2~3 倍。所以"448 + 全层 + 多 prompt"这个组合最吃显存，`layer_index=-2` 的默认值正是在这里做的权衡。

### 7.4 版本耦合风险

hook 是逐字拷贝的函数体，被 hook 的库一改内部实现就会出问题：

| 变化类型 | 后果 |
| --- | --- |
| `ResidualAttentionBlock` 换属性名（`self.attn` ↔ `self.attention`） | `AttributeError` |
| `forward` 签名变（`q_x` → `x`） | `TypeError` |
| `F.multi_head_attention_forward` 内部实现调整 | **不报错**，但 hook 版与真实前向数值不一致 → 解释的不再是模型真正在做的事 |

第三类最隐蔽。`requirements.txt` 钉了 `open_clip_torch<=2.23.0` 就是这个原因。升级 open_clip / timm / torch 前，务必先做 sanity check：同一张图同一 prompt，比对升级前后的热图是否逐元素一致。
