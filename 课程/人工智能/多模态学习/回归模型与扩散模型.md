## 一、问题背景

原始速记中提到 SORA 的“切割图片”，以及这种表示如何同时服务于 regression model 和 diffusion model。这里可以先拆成两个层次：

- **表示层**：把图像或视频切成规则的局部块（patch），再把每个 patch 压缩、投影为向量，形成模型可以处理的连续 token 序列。
- **生成目标层**：模型可以直接回归某个连续目标，也可以学习从噪声逐步还原数据的扩散过程。

因此，“切割图片”主要解决输入和输出的表示问题，不会自动决定模型属于回归模型还是扩散模型。它与[[../tokenizer/Tokenizer原理与BPE|Tokenizer]]中“用合适的压缩尺度减少序列长度”的思想相近，只是视觉 token 通常来自空间或时空 patch，而不是文本子词。

## 二、回归模型：直接预测目标

### 2.1 目标

回归模型学习一个映射：

$$
f_\theta(x, c) \approx y
$$

其中 $x$ 是输入，$c$ 是条件信息，$y$ 是连续目标。训练时直接比较预测值与真实值的差异，例如：

$$
\mathcal{L}_{\mathrm{MSE}}=\mathbb{E}\left[\|f_\theta(x,c)-y\|_2^2\right]
$$

图像任务中的 $y$ 可以是像素、特征、深度、光流、边界框坐标或下一步的连续 latent。分类任务也常被放在“判别式预测”一侧讨论，但严格说分类输出是离散标签，不是连续回归。

### 2.2 训练与推理

训练时，把输入和目标同时提供给模型，优化预测误差。推理时通常执行一次或少量几次前向计算，直接得到预测结果：

```text
输入 x、条件 c
    ↓
模型 fθ
    ↓
连续预测 ŷ
```

这种方式的优点是推理路径短、目标明确，适合：

- 图像中的深度、坐标、姿态、光流等估计；
- 图像或视频 patch 的特征预测；
- 给定上下文后预测下一帧 latent 或连续状态；
- 需要低延迟、单一确定性答案的任务。

局限在于：当一个条件对应多个合理答案时，使用单一的 MSE 预测，容易得到多个答案的平均结果。例如同一个文本可能对应多种构图，直接回归所有可能图像往往产生模糊或过度平滑的结果。回归模型也可以通过概率分布、混合密度或采样策略表达不确定性，但那已经超出了“只预测一个均值”的简单回归形式。

## 三、扩散模型：学习逐步去噪

### 3.1 目标

扩散模型不是一次性从条件直接输出清晰样本，而是先定义一个逐渐加噪的前向过程，再学习逆过程。对数据 $x_0$，可以表示为：

$$
q(x_t\mid x_0)=\mathcal{N}\left(\sqrt{\bar{\alpha}_t}x_0,\ (1-\bar{\alpha}_t)I\right)
$$

模型学习在给定时间步 $t$、带噪样本 $x_t$ 和条件 $c$ 时，预测噪声、干净样本或速度参数化目标。以噪声预测为例：

$$
\mathcal{L}=\mathbb{E}_{x_0,\epsilon,t}\left[
\|\epsilon-\epsilon_\theta(x_t,t,c)\|_2^2
\right]
$$

这里的 MSE 仍然存在，但它衡量的是“噪声或相关参数的预测误差”，不能因此把整个模型简单等同为普通回归模型。

### 3.2 训练与采样

训练阶段随机选取时间步，把真实样本加噪后交给模型，要求模型估计去噪所需的信息。采样阶段从随机噪声开始，按时间步反复调用模型：

```text
纯噪声 xT
    ↓ 反复去噪
xT → xT-1 → ... → x1 → x0
    ↑
文本、图像或视频条件
```

扩散采样的核心优势是能表示多峰分布：同一个条件可以通过不同随机种子产生多个合理结果。这使它适合文本生图、图像编辑、视频生成、超分辨率和条件补全等任务。代价是通常需要多次网络调用，推理延迟和计算量高于一次前向的直接回归；快速采样、蒸馏和少步数求解器可以降低这一代价，但效果取决于模型和任务。

## 四、二者的关系与区别

| 维度 | 回归模型 | 扩散模型 |
| --- | --- | --- |
| 直接目标 | 预测目标 $y$ 或某个连续表示 | 预测不同噪声水平下的去噪方向或相关参数 |
| 推理方式 | 一次或少量前向计算 | 从噪声开始，多步迭代采样 |
| 多解表达 | 简单 MSE 容易趋向平均解 | 随机采样更自然地表达多种解 |
| 常见优势 | 低延迟、数值预测直接 | 生成质量和分布覆盖通常更强 |
| 主要代价 | 可能过度平滑或忽略不确定性 | 采样步数多、推理成本较高 |

“回归”和“扩散”不是完全互斥的标签。扩散模型每一步也在做连续值预测；回归模型也可以输出分布参数，甚至配合随机采样。更准确的区分方式是看**整体生成机制**：是直接映射到目标，还是通过一系列噪声状态近似数据分布并逐步采样。

## 五、多模态 patch 与 token 表示

### 5.1 从图像到 patch

设图像大小为 $H\times W$，patch 边长为 $p$，通道数为 $C$。将图像切分后，patch 数量大致为：

$$
N=\frac{H}{p}\cdot\frac{W}{p}
$$

每个 patch 的原始维度为 $p^2C$，经过线性层或视觉编码器映射到 $d$ 维向量：

$$
z_i=E(\operatorname{patch}_i)+e_i
$$

其中 $e_i$ 可以携带空间位置或时间位置。视频还要沿时间轴切分，得到时空 patch，token 数量近似为：

$$
N_{\mathrm{video}}
\approx
\frac{T}{p_t}\cdot\frac{H}{p_h}\cdot\frac{W}{p_w}
$$

patch 越小，空间细节越丰富，但 token 数量和注意力成本上升；patch 越大，序列更短，但细节可能损失。这是视觉 token 化中的压缩尺度取舍，不存在对所有任务都最优的固定大小。

### 5.2 为什么同一表示可以支持不同目标

patch 序列本质上是对图像或视频的连续表示。基于同一表示，模型可以：

- 做回归：预测下一组 patch 的 latent、深度值或运动信息；
- 做扩散：对 patch latent 加噪，学习在条件下逐步还原；
- 做理解：把 patch 向量送入 Transformer，与文本 token 进行交叉注意力或统一序列建模。

这也是“统一视觉表示”有价值的原因：表示层与预测头、训练目标可以解耦。以 SORA 为例，不能仅凭“切成 patch”这一描述断言它就是回归模型；需要进一步看其训练目标和采样过程。若采用视频 latent、时空 patch 和扩散式去噪，patch 是扩散 Transformer 处理的数据单元，而不是扩散和普通回归各自必须拥有一套完全不同的图片切割方法。

## 六、JSON 与 YAML 对 token 和模型输入的影响

### 6.1 token 数量不是由格式名称决定

JSON 和 YAML 可以表达相同的键值结构，但实际 token 数量取决于：

- 所用 tokenizer 的词表和合并规则；
- 键名、缩进、引号、逗号、冒号等字符是否容易被合并；
- 字符串内容、空格和换行；
- 是否重复字段名，以及是否存在长键名。

例如同一份内容可能写成：

```json
{"model":"diffusion","steps":30,"size":[1024,1024]}
```

也可能写成：

```yaml
model: diffusion
steps: 30
size: [1024, 1024]
```

在某些 tokenizer 下，YAML 因为省略了大量引号和逗号，token 数量可能更少；但这不是语言层面的保证。短 JSON 键名、特定 tokenizer 的合并规则或 YAML 中复杂的缩进和长文本，都可能使差异缩小，甚至反转。应使用目标模型的 tokenizer 对真实样本计数，而不是凭格式名称估算。

### 6.2 成本与可靠性的权衡

token 更少通常意味着更低的输入成本、更大的有效上下文空间和较低的注意力计算量，但不能单独作为格式选择标准。

- **JSON**：语法边界清晰、解析器和 Schema 生态成熟，适合 API、工具调用、机器间传输和严格校验。代价是引号、逗号和括号较多，某些输入下会增加 token。
- **YAML**：对人阅读较友好，重复结构可以省略部分标点，可能降低 token 数；但缩进敏感，隐式类型、特殊字符、多行字符串和不同解析器行为可能带来歧义。

当模型需要输出后直接交给程序执行时，结构可靠性通常比节省少量 token 更重要。可以使用 JSON Schema、类型校验、字段白名单和错误重试来约束 JSON；使用 YAML 时，应限定语法子集、明确缩进规则，并在进入业务逻辑前完成解析与类型校验。模型读配置而不是生成接口负载时，YAML 可能更紧凑，但仍应通过实际 token 统计和解析测试验证。

### 6.3 实用决策

1. 先判断数据的主要消费者：人、语言模型，还是严格的程序接口。
2. 对固定数据集分别用目标 tokenizer 统计 JSON 与 YAML 的 token 数。
3. 评估解析失败、字段遗漏、类型误读和注入风险，而不只比较长度。
4. 若输入很长，优先减少重复字段、无关说明和冗余历史；格式本身带来的节省通常只是整体成本的一部分。
5. 若输出必须可执行，采用明确 Schema 的 JSON 往往更稳；若主要目标是人和模型共同阅读，可评估受限 YAML 或更简洁的键值表示。

格式优化的合理结论是：**在语义不变和可校验的前提下，选择经过实测更紧凑的表示**，而不是把 YAML 或 JSON 绝对化地称为“更省 token”或“更可靠”。
