SLR(1)（Simple LR）分析法是在 [[LR(0)]] 的基础上，通过向前查看一个输入符号来解决简单的冲突问题。它依然使用 LR(0) 的项目集族，但在构造分析表时更加谨慎，利用了[[LL(1)分析法#1.2 FOLLOW 集 (后跟符号集)|FOLLOW 集]]的全局信息。

## 1. 算法核心差异

状态转移（移进和 Goto）的处理与 LR(0) 完全一致，构造 DFA 的过程也完全相同。核心区别在于**归约动作**的判定：
- **移进 (Shift)**：若 $\text{Goto}(I_i, a) = I_j$，则在表中填入 $s_j$。
- **归约 (Reduce)**：若项目 $A \to \alpha \cdot$ 在 $I_i$ 中，**仅当**当前输入符号 $a \in \text{FOLLOW}(A)$ 时，才在表中填入 $r_n$。

## 2. 实例演示

为了展示 SLR(1) 如何解决 LR(0) 无法处理的冲突，我们使用一个简单的算术表达式文法：

0. $S' \to E$
1. $E \to E + T$
2. $E \to T$
3. $T \to \text{id}$

计算所需的 FOLLOW 集：
- $\text{FOLLOW}(E) = \{ +, \$ \}$
- $\text{FOLLOW}(T) = \{ +, \$ \}$

### 2.1 构造项目集族与 DFA

LR(0) 项目集族如下：
- **$I_0$**: $S' \to \cdot E$ ; $E \to \cdot E + T$ ; $E \to \cdot T$ ; $T \to \cdot \text{id}$
- **$I_1$**: $S' \to E \cdot$ ; $E \to E \cdot + T$
- **$I_2$**: $E \to T \cdot$
- **$I_3$**: $T \to \text{id} \cdot$
- **$I_4$**: $E \to E + \cdot T$ ; $T \to \cdot \text{id}$
- **$I_5$**: $E \to E + T \cdot$

对应的 DFA 状态转移图：

![[assets/SLR1_DFA.svg]]

如果使用 LR(0)，在状态 1 遇到 `+` 时，由于存在归约项目，它会在所有列（包括 `+`）填入归约；同时 `+` 又是移进符号。这就产生了严重的[[LR冲突|移进-归约冲突]]。

### 2.2 SLR(1) 解决冲突与构建分析表

利用 SLR(1) 的规则：
对于状态 1 中的 $S' \to E \cdot$，由于 $\text{FOLLOW}(S') = \{ \$ \}$，我们**仅在 `$` 列填入 Accept（归约）**。
对于 `+` 列，由于 `+` 不在 $\text{FOLLOW}(S')$ 中，我们只填入移进动作 $s_4$。冲突成功化解！

| 状态    | id    | +     | $      | E   | T   |
| :---- | :---- | :---- | :----- | :-- | :-- |
| **0** | $s_3$ |       |        | 1   | 2   |
| **1** |       | $s_4$ | Accept |     |     |
| **2** |       | $r_2$ | $r_2$  |     |     |
| **3** |       | $r_3$ | $r_3$  |     |     |
| **4** | $s_3$ |       |        |     | 5   |
| **5** |       | $r_1$ | $r_1$  |     |     |

*(注：在状态 2 和 5 中，由于 $\text{FOLLOW}(E)$ 和 $\text{FOLLOW}(T)$ 均包含 `+` 和 `$`，因此在对应的列填入归约动作。)*

## 3. 局限性

当状态 $I_i$ 中同时存在移进和归约项目时，只要移进符号不在对应非终结符的 FOLLOW 集中，SLR(1) 就能化解冲突。

然而，SLR(1) 仅利用了全局的 $\text{FOLLOW}$ 集合，而没有考虑特定的上下文环境。有时即使 $a \in \text{FOLLOW}(A)$，在当前特定的 DFA 状态下进行归约在逻辑上也是不合法的（即假冲突）。要解决这种上下文敏感的冲突，我们需要更强大的 [[LR(1)]] 分析法。
