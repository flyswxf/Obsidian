语法分析是编译过程的第二阶段。它的主要任务是：接收词法分析器提供的 Token 流，根据语言的语法规则（通常由[[上下文无关文法]]描述），构建出一棵[[语法树]]（或抽象语法树 AST），从而检查输入的程序是否符合语法规则。

例如语法规则 `变量声明 → 类型 标识符 分号`，语法分析器只需依次检查当前 Token 是否为 “类型关键字”“标识符”“分号”，即可判断语句是否合法。

## 2. [[上下文无关文法]] (Context-Free Grammar, CFG)

上下文无关文法是形式语言理论中用于描述编程语言语法结构的数学模型。它通常由四元组 $G = (V, T, P, S)$ 构成，其中包含非终结符集合、终结符集合、产生式规则以及开始符号。CFG 能够有效描述程序中的嵌套结构（如括号匹配、控制流块）。

---

## 3. 自顶向下分析 (Top-Down Parsing)

从文法的开始符号出发，尝试推导出与输入符号串完全匹配的句子（构建[[语法树]]的过程从根节点到叶节点）。

### 3.1 递归下降分析 (Recursive Descent Parsing)

- 为每个非终结符编写一个递归函数。
- **缺点**：如果文法包含**左递归**（如 $A \to A \alpha$），会导致函数无限循环调用自己。

### 3.2 [[LL(1)分析法]]

LL(1) 分析法是一种不需要回溯的高效自顶向下分析方法。
其名称含义为：从**左到右扫描输入流（Left-to-right）**，**构建[[推导#最左推导 (Leftmost Derivation)|最左推导]]**，并在**做出分析决策时向前查看 1 个记号**。

实现 LL(1) 的前提是[[消除左递归|消除文法的左递归]]并[[提取公共左因子]]，从而确保基于 $\text{FIRST}$ 与 $\text{FOLLOW}$ 集合构建的预测分析表无冲突。

---

## 4. 自底向上分析 (Bottom-Up Parsing)

从输入符号串开始，尝试将其归约（Reduce）为文法的开始符号。通常采用**移进-归约 (Shift-Reduce)** 工作方式。

### 4.1 核心概念：句柄 (Handle)

在自底向上分析中，句柄是指与某个产生式右部匹配的子串，并且将它归约到该产生式左部代表了[[推导#最右推导 (Rightmost Derivation)|最右推导]]的逆过程的一步。简而言之，句柄就是当前栈顶最应该被归约的子串。每次**归约** (Reduce) 操作的本质，就是在栈顶寻找并替换句柄。

### 4.2 LR 分析法
依靠状态栈和符号栈进行分析，通过构造 DFA（有限状态自动机）来识别归约时机。
![[LR架构.png]]

#### LR 分析器的核心组件：
1. **输入串 (Input)**：包含将要被分析的词法记号（Token）流，以结束符 `$` 结尾（$a_1 \dots a_i \dots a_n \$$）。
2. **栈 (Stack)**：用于记录从初始状态到当前状态的推导历史。逻辑上，栈内交替存放状态与文法符号（$S_0 X_1 S_1 X_2 \dots X_m S_m$），其中 $S_0$ 为初始状态。在具体实现中，通常将其拆分为两个同步工作的平行栈：
	- **状态栈 (State Stack)**：存放底层的 DFA 状态（$S_i$）。当前的栈顶状态决定了分析器下一步的动作（通过查 Action 表）。
	- **符号栈 (Symbol Stack)**：存放终结符和非终结符（$X_i$）。栈顶的若干连续符号构成了即将被归约的句柄。
	- **栈的动态变化规则**：
		- **移进 (Shift)**：将当前输入符号 $a$ 压入符号栈，并根据 Action 表将新状态 $S'$ 压入状态栈。
		- **归约 (Reduce)**：若按产生式 $A \to \beta$ 归约，需从两个栈顶分别弹出 $|\beta|$ 个元素。随后将左部符号 $A$ 压入符号栈，并根据此时状态栈暴露出的新栈顶状态与 $A$ 查 Goto 表，将得到的新转移状态压入状态栈。
3. **分析表 (Parsing Tables)**：由两部分组成：
	- **Action 表（动作表）**：以状态和**终结符**（含 `$`）为索引，指示分析器当前应执行的四种动作之一（移进 Shift、归约 Reduce、接受 Accept、报错 Error）。
	- **Goto 表（状态转移表）**：以状态和**非终结符**为索引，指示在完成一次归约后，分析器应转移到的下一个状态号。
	- 所有用于构造 LR 分析表的文法都必须是[[二义性文法(Ambiguous Grammar)|无二义性的]]
		![[分析表.png]]
4. **LR 分析程序 (LR Parsing Algorithm)**：核心控制引擎，根据栈顶状态和当前输入符号，查阅分析表并执行相应的动作，最终输出语法树或归约序列。

- **LR 家族**（按分析能力由弱到强）：
  1. **[[LR(0)]]**：不向前查看输入符号，仅依赖当前栈顶状态进行归约。
  2. **[[SLR(1)]]**：向前查看一个输入符号，利用全局 $\text{FOLLOW}$ 集合解决部分移进-归约冲突。
  3. **[[LR(1)]]**：在项目集中精确携带向前查看符号（Lookahead），拥有最强的分析能力，但会导致状态机规模庞大。
  4. **[[LALR(1)]]**：合并 LR(1) 中具有相同核心的项目集，在保持较强分析能力的同时大幅缩减状态空间规模。**Yacc / Bison** 等工业级工具主要采用 LALR(1)。

## 5. 抽象语法树 (AST) 与输出

语法分析的最终输出通常是[[语法树#抽象语法树 (Abstract Syntax Tree, AST)|抽象语法树 (AST)]]，而不是包含所有推导细节的具体分析树（Parse Tree）。
AST 移除了括号等仅为满足语法规则而存在的冗余节点，仅保留程序的核心计算结构，其紧凑的结构更适合后续阶段（如语义分析与目标代码生成）进行处理。

## 6. 错误处理

- **恐慌模式 (Panic-mode)**：丢弃输入流中的记号，直到遇到一个同步记号（如分号、右大括号），然后继续分析。
  > 示例：若缺失语句终结符，编译器将跳过后续无法解析的词法单元，直至匹配到下一个合法终结符以恢复状态。
- **短语层次恢复 (Phrase-level recovery)**：在特定位置执行局部的修改（如插入缺失的标点符号或删除冗余符号），尝试修复错误并继续语法分析过程。
