### 一、函数依赖集（Functional Dependency Set）的定义与表示方法  
**定义**：  
函数依赖（FD）是关系数据库中的一种约束条件，用于描述属性之间的逻辑关系。形式化定义为：  
若在一张关系表中，属性集合 **α** 的值能唯一确定属性集合 **β** 的值，则称 **α 函数决定 β**，记作 **α → β**。  
• **α** 称为函数依赖的 **左部**（Left-Hand Side, LHS），**β** 称为 **右部**（Right-Hand Side, RHS）。  

**表示方法**：  
函数依赖集 **F** 是一组函数依赖的集合，通常用于描述整个关系模式中的所有已知约束。例如：  
• **F = { A → B, B → C }** 表示：  
  1. 属性 A 的值唯一决定属性 B 的值；  
  2. 属性 B 的值唯一决定属性 C 的值。  

---

### 二、函数依赖集的闭包（Closure of FDs Set）  
**定义**：  
给定函数依赖集 **F**，其闭包 **F+** 是 **F 逻辑蕴含的所有函数依赖的集合**。即：  
• **F+** 包含 F 中已有的所有 FD，以及通过阿姆斯壮公理（Armstrong's Axioms）从 F 推导出的所有新 FD。  

**意义**：  
闭包 **F+** 是关系数据库设计的核心工具，用于：  
1. 验证数据库设计的合理性（如是否满足范式）；  
2. 确保所有可能的依赖关系均被覆盖。  

**闭包的表示**
```
F+ = {Φ-> {Φ}, A->{Φ, A, B, C, AB, AC, BC, ABC}, B->{Φ, B, C, BC}, C=>{Φ, C},

      AB->{Φ, A, B, C, AB, AC, BC, ABC}, AC->{Φ, A, B, C, AB, AC, BC, ABC},

	  BC->{Φ, B, C, BC}, ABC->{Φ, A, B, C, AB, AC, BC, ABC} }
```

### 三、阿姆斯壮公理（Armstrong's Axioms）  
阿姆斯壮公理是一组**可靠且完备**的推理规则，用于从已知函数依赖推导出闭包 **F+** 中的所有依赖。  

#### 1. 基本公理  
• **自反律（Reflexivity Rule）**：  
  若 **β ⊆ α**，则 **α → β**。  
  • *例*：若 α = {A, B}, β = {A}，则 {A, B} → {A}。  

• **增广律（Augmentation Rule）**：  
  若 **α → β**，则对任意属性集 **γ**，有 **γα → γβ**。  
  • *例*：若 α → β，且 γ = {C}，则 {C, A} → {C, B}。  

• **传递律（Transitivity Rule）**：  
  若 **α → β** 且 **β → γ**，则 **α → γ**。  
  • *例*：若 {A} → {B} 且 {B} → {C}，则 {A} → {C}。  

#### 2. 附加规则（由基本公理导出）  
• **并规则（Union Rule）**：  
  若 **α → β** 和 **α → γ** 成立，则 **α → βγ** 成立。  
  • *用途*：合并右侧的依赖。  

• **分解规则（Decomposition Rule）**：  
  若 **α → βγ** 成立，则 **α → β** 和 **α → γ** 均成立。  
  • *用途*：拆分右侧的依赖。  

• **伪传递规则（Pseudotransitivity Rule）**：  
  若 **α → β** 且 **γβ → δ**，则 **αγ → δ**。  
  • *例*：若 {A} → {B} 且 {B, C} → {D}，则 {A, C} → {D}。  

---

### 四、关键总结  
1. **函数依赖集 F** 是显式声明的依赖集合；  
2. **闭包 F+** 是隐式包含所有逻辑推导结果的依赖集合；  
3. **阿姆斯壮公理** 提供了从 F 推导 F+ 的规则，无需依赖具体数据，仅通过逻辑推理即可完成。  

通过掌握这些规则，可以系统化地分析数据库设计中的约束关系，确保数据的一致性与完整性。
