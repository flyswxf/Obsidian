### 📖 什么是规范覆盖（Canonical Cover）？

在数据库范式设计中，我们经常需要对**函数依赖集（FD Set）**进行化简，化简后的依赖集叫做**规范覆盖**（Canonical Cover 或 Minimal Cover）。

简单理解： 👉 **它是跟原始依赖集逻辑等价，但更简洁、无冗余、结构清晰的形式。**

---

### 📌 规范覆盖 Fc 的定义条件

#### ① 双向逻辑蕴含

必须保证：

- **原依赖集 F 蕴含化简后的 Fc**
    
- **化简后的 Fc 也蕴含原依赖集 F**
    

也就是说，**F 和 Fc 推导出来的所有可能依赖是一样的**，只是表达方式更简洁。

✔️ 记法：

- F → Fc
    
- Fc → F
    

#### ② 无冗余属性

- **Fc 中不能有无用的属性**，也就是说：
    
    - **左边不能有多余属性**，去掉之后要保证依赖还成立。
        
    - **右边不能有多余属性**，如果右边是复合属性，也要判断其中的属性是不是冗余。
        

👉 比如：

- 如果有 `A B → C`，但 `A → C` 也成立，那 B 就是冗余。
    

#### ③ 左部唯一性

- **Fc 中任何两个依赖的左边不能一样**。
    
    - 如果有相同左边的，应该合并右边。
        

👉 比如：

- 有 `A → B` 和 `A → C`，那就应该合并成 `A → BC`
    

---

### 📌 规范覆盖求法基本步骤（简化版）

1. **右边拆分**：  
    把右边有多个属性的依赖，拆成多个单属性依赖。  
    例如： `A → BC` 拆成 `A → B` 和 `A → C`
    
2. **消除左边冗余属性**：  
    对每个依赖，看看左边去掉某个属性后，是否还能推出右边。能的话就删掉。
    
3. **去掉多余依赖**：  
    如果去掉某个依赖，剩下的依赖还能推导出原来的依赖集，就删掉。
    
4. **合并左部相同的依赖**：  
    比如 `A → B` 和 `A → C`，合成 `A → BC`
    

---

### 📌 举个例子

原函数依赖集：

```
F = { A B → C, A → B, C → A }
```

求规范覆盖：

1. **右边拆分**  
    AB → C 右边只有一个，不用拆  
    A → B  
    C → A  
    不用动
    
2. **消左边冗余**  
    AB → C，看能不能去掉 A 或 B
    
    - 看 `B → C` 是否成立？不成立
        
    - 看 `A → C` 是否成立？
        
        - A → B，B → C 还不行（因为没有 B → C）  
            → 保留 AB → C
            
3. **去掉多余依赖**  
    看是否可以去掉某条
    
    - 去掉 A → B 后，是否能推导出？
        
        - AB → C，C → A
            
        - C → A → B？不行  
            → A → B 不能删
            
4. **合并左边相同的**  
    没有相同左边的，OK
    

最终规范覆盖：

```
Fc = { AB → C, A → B, C → A }
```

（这个例子原来就已经是规范覆盖了）

---

### 📌 总结

规范覆盖就是：

> **在不改变逻辑含义的前提下，删去冗余，拆分右边，合并左边，得到最简洁唯一的等价函数依赖集。**
