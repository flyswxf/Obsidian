入侵检测系统（Intrusion Detection System）是一种监控网络或系统活动，检测恶意行为或策略违规，并发出警报的安全机制。与[[防火墙]]不同，IDS 侧重于检测而非必然阻止危险。

## 核心组件

入侵检测系统通常由以下核心组件构成：
- **传感器（Sensor）**：负责收集数据，如网络数据包、日志文件、系统调用等。
- **分析器（Analyzer）**：接收传感器的数据，运用特定的检测算法判断是否存在入侵行为。
- **管理控制台（Manager）**：提供统一的用户界面，用于配置策略、查看警报、管理传感器及分析器。

## 分类

根据监控范围和部署位置的不同，入侵检测系统主要分为两类：
- **[[主机入侵检测]]**：部署在单台主机上，监控操作系统内部的活动（如系统调用、文件完整性）。
- **[[网络入侵检测]]**：部署在网络节点上，监控跨越网段的网络流量。

两者在防御体系中构成互补关系，结合使用可实现纵深防御。

| 维度         | 主机入侵检测 (HIDS)      | 网络入侵检测 (NIDS)            |
| ------------ | ------------------------ | ------------------------------ |
| **部署位置** | 主机内部                 | 网络节点                       |
| **监控范围** | 单台主机                 | 整个网络段                     |
| **数据源**   | 系统日志、文件、进程     | 网络流量                       |
| **加密流量** | 可检测（数据解密后）     | 无法直接解析                   |
| **内部威胁** | 能够有效捕获             | 通常存在监控盲区               |
| **规避难度** | 难（需深入操作系统底层） | 易（可通过加密或隧道技术规避） |

NIDS 负责网络层面的广泛监控，而 HIDS 弥补了 NIDS 在加密流量和深层系统活动上的盲区。

## 基率谬误 (Base-Rate Fallacy)

在实际网络环境中，正常流量占 99.9% 以上，攻击流量不到 0.1%。在如此悬殊的比例下，即使 IDS 的误报率极低，也会产生大量假警报。这是入侵检测面临的核心难题。

### 误报 vs 漏报

| 维度     | 误报 (False Positive) | 漏报 (False Negative) |
| -------- | --------------------- | --------------------- |
| **含义** | 正常事件被当作攻击    | 攻击事件未被检测到    |
| **后果** | 警报疲劳，浪费人力    | 攻击成功，造成损失    |

降低误报率通常会导致漏报率上升，反之亦然。IDS 设计的核心就是在两者之间找到最优平衡点。
