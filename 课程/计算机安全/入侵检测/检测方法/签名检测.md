签名检测（Signature-based Detection），又称为误用检测，主要依赖于预先定义的恶意行为模式数据库。该方法通过将被监控的系统事件或网络流量与已知的攻击特征（签名）进行模式匹配。一旦发现严格吻合的模式，系统便触发入侵检测警报。

常见的签名形式包括特定字符串序列、特定字节序列或特定的正则表达式。例如，网络数据包中包含已知的恶意载荷特征。

### 例子
- **网络流量分析**：若网络流量中出现特定的字符串（如 HTTP 请求中的 `GET /etc/passwd` 或包含恶意的 `<script>` 标签），系统判定为潜在攻击（如路径穿越或跨站脚本 XSS）；若在 1 分钟内同一 IP 探测了超过 50 个端口，则触发端口扫描警报。
- **主机系统分析**：比对已知恶意软件的哈希值（文件签名），或匹配特定的日志输出（如大量的 `Failed password for root`）以及高危系统配置（如 SSH 允许 root 直接登录）。

## 技术特点
- **高准确率**：针对已知威胁的检测具有极高的准确性，误报率通常极低。
- **计算效率高**：模式匹配算法（如 Aho-Corasick 多模式匹配算法）能够在高速网络中实时执行。
- **状态维护简单**：部分签名匹配仅依赖单个数据包的静态特征，无需复杂的上下文状态维护。

## 局限性
签名检测的核心缺陷在于其被动性：
- **无法应对未知威胁**：完全无法检测零日漏洞（Zero-day exploits）或未被收录的新型变种攻击。
- **数据库维护成本高**：需要持续、及时地更新签名数据库，以保证检测能力的时效性。
- **易受规避攻击**：攻击者可通过加密、多态变形或分片技术轻易绕过基于固定模式的检测。
