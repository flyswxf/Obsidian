蜜罐就是一个**故意暴露的假系统**，看起来像真实服务器，实际是陷阱。攻击者以为自己找到了目标，实际上他的一举一动都在被监控和记录。

> 核心价值：**不是为了防御，而是为了收集情报和转移注意力**。

## 按交互程度分类

| 类型      | 像什么                 | 优点             | 缺点               |
| ------- | ------------------- | -------------- | ---------------- |
| **低交互** | 只开放几个端口，模拟服务 Banner | 部署简单，风险低       | 攻击者很快就跑，信息收集有限   |
| **中交互** | 模拟完整服务，能"对话"        | 能收集更多攻击细节      | 需要更多维护           |
| **高交互** | 就是一个真实系统            | 攻击者完全不知情，信息最丰富 | 风险高——攻击者可能反过来利用它 |
## 按规模分类

| 类型 | 说明 |
| ---- | ---- |
| **蜜罐 (Honeypot)** | 单个诱饵系统 |
| **蜜网 (Honeynet)** | 多个蜜罐组成的"假网络" |
| **蜜 token** | 嵌入真实系统的诱饵数据 |
| **蜜文件 (Honeyfile)** | 放在服务器上的"诱饵文件" |

> [!example] 蜜 token 典型用法
> - 在数据库里放一条假的管理员密码记录 → 有人查询它 → 说明数据库被入侵了
> - 在代码仓库里放一个假的 AWS 密钥 → 有人使用它 → 说明代码泄露了
> - 在文件系统里放一个叫 `passwords.txt` 的诱饵文件 → 有人打开了它 → 说明有内鬼或入侵者

## 蜜罐能收集什么情报？

| 情报类型 | 价值 |
| -------- | ---- |
| **攻击工具** | 了解攻击者用什么软件 |
| **攻击手法** | 了解攻击怎么实施的 |
| **攻击来源** | IP、地理位置 |
| **恶意软件样本** | 用于分析和签名提取 |
| **攻击动机** | 是随机扫描还是定向攻击？ |
## 蜜罐的实战价值

> [!example] 案例：零日攻击发现
> 1. 蜜罐捕获到未知恶意软件
> 2. 安全团队分析攻击行为和载荷
> 3. 提取攻击特征（IOC）
> 4. 识别零日漏洞
> 5. 通知厂商修补
> 6. 将特征推送到全网 IDS 签名库

> [!example] 案例：增强 IDS 检测能力
> 蜜罐检测到新攻击 → 提取签名 → 更新 IDS 签名库 → 全网部署新规则 → 检测同类攻击
>
> 这就是蜜罐与 [[入侵检测系统（IDS）|IDS]] 的协同效应：蜜罐负责"养蛊"（引诱攻击者），IDS 负责"撒网"（全网检测）。
