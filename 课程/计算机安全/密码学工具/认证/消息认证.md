消息认证是一种确保**收到的消息确实是声称的发送方所发出、且内容未被篡改**的密码学机制。它回答两个关键问题：
1. **消息来源是否可信？** —— 发送方认证 (Source / Data Origin Authentication)
2. **消息是否被修改过？** —— 完整性保护 (Integrity Protection)

### 与机密性的区别

消息认证和消息加密是**两个独立的安全目标**：

| 安全目标     | 解决的问题           | 典型实现                               |
| -------- | --------------- | ---------------------------------- |
| **机密性**  | 外人能否读取消息内容？     | [[对称加密\|对称加密]]、[[非对称加密\|非对称加密]]    |
| **消息认证** | 消息是否来自可信方且未被篡改？ | [[消息认证码(MAC)\|MAC]]、[[数字签名\|数字签名]] |

> 加密**不自动提供**认证，认证**不自动提供**加密。两者需要分别实现。

## 消息认证提供的安全服务

### 消息完整性 (Message Integrity)
确保消息在传输过程中未被任何方式（意外或恶意）修改。

**实现原理：** 认证标签/签名是消息内容的密码学函数。任何对消息的修改都会导致验证失败。

### 消息来源认证 (Data Origin Authentication)
确保消息确实来自声称的发送方。

**实现原理：**
- MAC：只有知晓共享密钥的双方能生成有效标签
- DS：只有私钥持有者能生成有效签名

### 不可抵赖性 (Non-Repudiation) 
确保消息的发送方事后无法否认其曾经发送过该消息。提供可供第三方验证的证据，以解决通信双方可能产生的纠纷。

|          |               MAC               |          DS          |
| -------- | :-----------------------------: | :------------------: |
| 提供不可抵赖性？ |                ❌                |          ✅           |
| 原因       | 发送方和接收方持有同一密钥，接收方 可自行生成任何 MAC 值 | 只有发送方有私钥，接收方无法伪造有效签名 |

## 机密性与认证的复合：认证加密 (Authenticated Encryption)

在实际通信系统中，**机密性和消息认证通常需要同时满足**。现代密码学提倡使用认证加密模式，将两者合并为一个安全操作。

### 三种组合策略及其安全性

| 策略                 | 描述                         | 安全性                           |
| -------------------- | ---------------------------- | -------------------------------- |
| **Encrypt-then-MAC** | 先加密，再对密文计算 MAC     | ✅ 推荐，最安全                   |
| **Encrypt-and-MAC**  | 分别对明文加密和计算 MAC     | ⚠️ MAC 可能泄露明文信息           |
| **MAC-then-Encrypt** | 先对明文计算 MAC，再一起加密 | ⚠️ 存在 padding oracle 等攻击风险 |
