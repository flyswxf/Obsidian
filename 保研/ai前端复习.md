坦白说，这是一个非常关键的问题。如果你在简历上写了一个非常亮眼的全栈项目，但实际是靠 "Vibe Coding"（即通过 Cursor/Trae 等 AI 辅助工具，通过自然语言对话堆出来的代码），一旦面试官深入挖掘底层逻辑和实现细节，很容易“露馅”。

为了在华为等大厂的面试中站稳脚跟，你需要**将 AI 辅助生成的代码“内化”为自己的知识体系**。

针对你简历中提到的 [简历.md](file:///d:/HuaweiMoveData/Users/fengl/Desktop/Obsidian/%E4%BF%9D%E7%A0%94/%E7%AE%80%E5%8E%86.md) 第 42-48 行的“智能学习日历与待办”项目，你需要重点突击以下四大模块：

### 1. 前端与 React 18 核心原理（必考基础）
由于项目明确写了基于 React Context 和 Vite，面试官一定会问你状态管理和性能优化的细节。
- **React 核心概念**：
  - 生命周期与 Hooks：`useEffect`（依赖数组的坑、清理函数）、`useState` 的异步性、`useMemo` 与 `useCallback` 的区别及应用场景。
  - **Context API**：你在简历中写了“基于 React Context 构建全局状态树”。你需要清楚 Context 是如何避免 Prop Drilling 的，以及它在状态频繁更新时带来的性能问题（组件全量重渲染）及解决方案。
  - 虚拟 DOM 与 Diff 算法：为什么要有虚拟 DOM？Fiber 架构解决了什么问题？
- **TypeScript 基础**：
  - `interface` 与 `type` 的区别。
  - 泛型（Generics）的基本使用。
  - 什么是 `any`、`unknown` 和 `never`？
- **Vite 机制**：为什么 Vite 比 Webpack 快？（基于 ESBuild 的预构建和基于原生 ESM 的按需加载）。

### 2. 离线架构与双写同步机制（项目最大亮点）
简历中提到“localStorage 优先与 Supabase 云端备份的双写同步机制”，这是面试官最感兴趣的工程化亮点。
- **LocalStorage 机制**：大小限制（通常 5MB），只能存字符串（为什么需要 `JSON.stringify/parse`）。
- **双写架构的难点（重点准备）**：
  - **一致性问题**：如果写本地成功，但写云端失败（比如断网）怎么办？（你需要了解重试机制、请求队列或“脏标记”思路）。
  - **数据冲突**：如果多设备同时修改了同一条数据，以哪个为准？（你需要了解乐观锁、时间戳对比或 LWW - Last Write Wins 策略）。
  - *应对策略：即使你在代码里没有实现这么复杂，你也要能在面试中说出“目前由于是单人使用场景，我采用了简单的时间戳覆盖策略，但如果要做大规模商业化，我会考虑引入 CRDT 算法或更完善的冲突解决机制”。*

### 3. AI 大模型 API 与 Prompt 工程（AI 岗位加分项）
你写了集成多模态大模型和 JSON Schema 约束。
- **API 调用机制**：前端直接调大模型 API 存在什么风险？（密钥泄露、CORS 跨域）。正确做法是通过后端（或 Serverless Function）转发请求。
- **结构化输出（JSON Schema）**：
  - 为什么大模型容易产生幻觉（幻觉问题）或输出非预期格式？
  - 你是如何通过 Prompt 约束大模型必须输出符合 JSON 规范的字段的？（举例：指定 `{"title": "string", "deadline": "YYYY-MM-DD"}` 的模板，设置 Temperature 参数等）。
- **多模态原理（了解即可）**：大模型是如何“看懂”图片的？（ViT 视觉 Transformer 结合 LLM 的基础概念）。

### 4. 复杂业务逻辑与算法实现（体现逻辑思维）
- **Mammoth.js 解析机制**：不需要懂 Mammoth 源码，但你要知道它大概是把 `.docx` 里的 XML 节点映射成 HTML 元素。
- **网格映射算法**：你在简历里写了处理 `rowspan/colspan`。你需要能在纸上（或白板上）大致画出一个二维数组，解释如何通过遍历填补被合并掉的空白单元格。
- **双策略时间推荐模型**：
  - 什么是 P25/P75 分位数？为什么要用分位数而不是平均值？（因为历史数据可能有极端离群值，比如你某次写作业摸鱼花了一整天，分位数可以过滤这种噪声）。
  - 什么是滑动窗口（Sliding Window）？（只取最近 N 天的数据，更能反映你当前的学习状态）。

### 💡 Vibe Coding 项目的面试生存指南（强烈建议）

1. **重新“审视”代码**：千万不要去背那些由 AI 生成的、你自己都看不懂的面条代码。打开项目，用自己的语言给每个核心模块（特别是 Context 状态管理和 Supabase 数据同步的地方）**写一遍中文注释**。
2. **准备“坑与反思”**：面试官最喜欢问：“项目中遇到过什么困难？怎么解决的？”如果是 Vibe Coding，你可能连坑在哪都不知道，因为 AI 直接给你写对了。
   - **你需要人为编造（或回忆）1-2 个技术坑**。
   - *举例：“一开始我把大模型 API 的调用直接写在 React 组件的 `useEffect` 里，导致组件一刷新就疯狂发请求，烧了很多 Token。后来我把它抽离到了独立的 Service 层，并加上了防抖机制。”*
3. **坦诚与包装并重**：如果面试官问到特别底层的实现细节你确实不会，**可以承认使用了 AI 辅助，但要把重点转移到你的架构设计能力上**。
   - *话术参考：“这个项目中很多具体的样板代码我是借助了 AI 工具（如 Cursor）来加速开发的。但我认为我的核心贡献在于**系统架构的设计**（比如双写同步怎么做）和**核心业务逻辑的梳理**（比如双策略时间推荐算法怎么跑）。作为开发者，我更倾向于把精力放在系统设计与 Prompt 调优上，让 AI 帮我完成基础实现。”* 这种回答在当下是非常高级且加分的。
