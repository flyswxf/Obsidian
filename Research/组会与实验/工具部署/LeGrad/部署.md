## 兼容性坑

### 1. RTX 5060 必须 torch ≥ 2.7.0+cu128

sm_120 的 kernel 从 `2.7.0+cu128` 才开始编进官方 wheel。装旧版 torch 会直接报 `no kernel image is available for execution on the device`。

### 2. `open_clip_torch` 必须 ≤ 2.23.0

`requirements.txt` 里的这条上限是硬约束。`hooked_resblock_forward` 复刻的是 2.23.0 的签名：

```python
def forward(self, q_x, k_x=None, v_x=None, attn_mask=None)
```

新版 open_clip 把它改回了单参数 `x`，升级后 hook 会直接替换失败或形状错乱。

### 3. `visualize()` 的 `save_path` 行为不符合直觉

`save_path` 只做真值判断，传什么字符串都一样；文件名固定为 `heatmap_<prompt>.png`，且落在**当前工作目录**。`repro.py` 的做法是先 `os.chdir(out_dir)` 再调用，返回后还原，避免污染仓库根目录。同时 prompt 原文会进文件名，含空格或斜杠时要重命名成安全字符。

### 4. parquet 的 `label` 字段不可靠

不能拿它当目标类。目标类必须以官方 `ImageNetS_im919_validation_names.txt` 里的 wnid 为准，再映射到 `categories.index(wnid) + 1`。`names` 与 `mapping` 有 1,652 张图不一致：`names` 是 ImageNet-S **修正后**的标签（与 mask 文件夹对齐），`mapping` 是 ImageNet-1k 原始标签。

### 5. 16 张图的 mask 不含目标类

`prepare` 阶段直接跳过，因此 `12,419 → 12,403`。另有 1 个多出的图像文件（12,420）是无对应 mask 的残留，不参与评测。

## 已知问题

- 所有脚本必须在 `D:\code\LeGrad` 下运行，否则 import 本地 `legrad` 包失败。
- 8 GB 显存跑 448 分辨率是单张前向的上限，不要改 batch；`eval` 阶段本身就是逐图串行的。
- `eval` 阶段用追加写 + 逐行 flush 实现断点续跑，同一 `--tag` 重跑只会补未完成的图；换超参必须换 `--tag`，否则新旧结果会混在一个文件里。
- `report` / `prepare` 不需要 GPU，但模块顶层 import 了 `cv2` 和 `pyarrow`，环境缺这两个包会直接起不来。
- 本地全量结果与原文表 1 存在系统性差距，原因分析见[[工作流#与原文表 1 的差距]]，不要直接判方法失效。
