## Deformable 算子兼容调整

旧版 SoM 使用了已废弃的 ATen API，需要调整两个文件：

```text
SoM/ops/src/cuda/ms_deform_attn.h
SoM/ops/src/cuda/ms_deform_attn_cuda.cu
```

### `ms_deform_attn.h`

```cpp
// 旧
value.type().is_cuda()

// 新
value.is_cuda()
```

### `ms_deform_attn_cuda.cu`

CUDA 判断：

```cpp
// 旧
value.type().is_cuda()

// 新
value.is_cuda()
```

类型分发：

```cpp
// 旧
AT_DISPATCH_FLOATING_TYPES(value.type(), "xxx", ([&] { ... }))

// 新
AT_DISPATCH_FLOATING_TYPES(value.scalar_type(), "xxx", ([&] { ... }))
```

数据指针：

```cpp
// 旧
tensor.data<scalar_t>()
tensor.data<int64_t>()

// 新
tensor.data_ptr<scalar_t>()
tensor.data_ptr<int64_t>()
```

修改后必须在 GPU 计算节点编译，因为 `setup.py` 需要 CUDA Runtime：

```bash
module load compiler/gnu/10.2.0
module load compiler/cuda/12.8
conda activate SoM

cd /public/home/yhhao/wyf/scenetap/SoM/ops
sh make.sh
```

当前编译产物已经存在：

```text
SoM/ops/build/lib.linux-x86_64-cpython-310/MultiScaleDeformableAttention.cpython-310-x86_64-linux-gnu.so
```

## 已知问题

- 登录节点没有 GPU，不要在登录节点运行 SoM 分割或 TextDiffuser 渲染。
- 计算节点不能访问外网，模型权重必须提前缓存，并启用 Hugging Face 离线模式。
- `DASHSCOPE_API_KEY` 只在登录节点按需注入，不要写入仓库、笔记或 Slurm 日志。
- SoM 与 TextDiffuser-2 的依赖版本不同，不要把两个环境合并。
- `xformers` 和 `torchvision` 不是当前 TextDiffuser 渲染路径的直接依赖；`torchvision` 已安装在需要它的 SoM 环境中。
