> [!important] 节点分工
> 登录节点负责联网规划、联网评估和轻量文件处理；GPU 计算节点负责 SoM 分割、TextDiffuser-2 渲染与 LLaVA 注意力实验。不要在登录节点加载模型或执行 CUDA 推理。

## 流程总览

| 阶段      | 脚本                          | 节点          | 环境              | 主要产物                  |
| ------- | --------------------------- | ----------- | --------------- | --------------------- |
| 1. 问题生成 | `generate_question_json.py` | 登录节点        | `textdiffuser2` | 问题 JSON               |
| 2. 场景分割 | `save_som_images.py`        | GPU 计算节点    | `SoM`           | 分割图、mask              |
| 3. 攻击规划 | `plan_attacks.py`           | 登录节点        | `textdiffuser2` | `attack_plans/*.json` |
| 4. 图像渲染 | `render_attacks.py`         | GPU 计算节点    | `textdiffuser2` | 攻击图、`renders.json`    |
| 5. 攻击评估 | `evaluate_attacks.py`       | 登录节点        | `textdiffuser2` | 回答文件、评估日志             |
| 6. 后续实验 | `exp1_baseline.py` 等        | GPU 计算节点    | `paa`           | ASR、注意力指标             |

数据流：

```text
原图和问题 JSON
    ↓
SoM 分割图与 mask
    ↓
LLM 攻击规划
    ↓
TextDiffuser-2 离线渲染
    ↓
renders.json 与攻击图
    ↓
LLM 评估 / 集群注意力实验
```

完整环境说明见[[部署]]。

## 7. 注意力分析实验

Physical-Attention-Attack 以 `prebuilt` 模式直接读取 SceneTAP 的 `renders.json` 和攻击图，不再经过 Kaggle 上传。实验通过 `jobs/` 下的 sbatch 脚本提交：

| 脚本                          | 分区   | 用途                      |
| --------------------------- | ---- | ----------------------- |
| `jobs/exp1_cluster.sbatch`  | gpu  | LLaVA 推理、注意力提取、ASR 统计   |
| `jobs/exp1_analysis.sbatch` | cpu  | 按攻击状态与 Patch 类型分组分析出图   |
| `jobs/download_model.py`    | 登录节点 | 下载模型权重                  |
| `jobs/check_env.py`         | 登录节点 | 环境与权重缓存自检               |
| `jobs/check_renders.py`     | 登录节点 | 校验 renders.json 图片路径可解析 |

小样本冒烟测试（3 张图）：

```bash
cd /public/home/yhhao/wyf/Physical-Attention-Attack

  jobs/exp1_cluster.sbatch
```

全量运行（51 条渲染记录，去掉 `EXP1_LIMIT` 即可）：


产物结构：

```text

├── attention_metrics.csv / .json      # 每试次 ASR 与注意力指标
├── experiment_report.json             # 汇总报告
├── attention_arrays/{no_patch,with_patch}/   # 注意力 npz
└── analysis_by_patch/                 # 分组箱线图与 summary
```

比较 `NO_PATCH` 与 `WITH_PATCH` 两组的 ASR，判断辅助 Patch 是否提高攻击成功率。

> [!note] 冒烟测试结果
> 作业 554029（gpu5，A100-40GB）3 张图 6 试次耗时约 9 分钟，总 ASR 33.33%（2/6），全部产物正常生成；分析作业 554436（cpu 分区）约 1 分钟完成。按此估算全量 51 张图约需 2–3 小时。

## 故障定位顺序

1. 问题 JSON 条数是否符合预期。
2. `slider`、`filter`、`seed` 是否在分割、规划和渲染阶段保持一致。
3. `som_images` 中是否同时存在分割图和 `.npy` mask。
4. `attack_plans` 的记录数是否与问题 JSON 一致。
5. 计算节点是否启用了 Hugging Face 离线模式。
6. `renders.json` 中记录的攻击图片路径是否存在。
7. 登录节点是否已加载 `DASHSCOPE_API_KEY`。
8. 评估输出条数是否与渲染记录数一致。
9. 注意力实验失败时先查 `Physical-Attention-Attack/logs/paa_exp1_*.err`，确认是环境、权重缓存还是图片路径问题。
10. `jobs/check_env.py` 是否确认 `paa` 环境依赖与 LLaVA 权重缓存完整。
