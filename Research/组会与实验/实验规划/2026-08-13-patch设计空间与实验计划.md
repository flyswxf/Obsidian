## 核心定位

当前方向不是继续优化基础的文字植入流程，而是在 [[2026-08-13-视觉注入攻击研究现状与后续实验|当前研究现状整理]] 的基础上，把 `patch` 明确为攻击词之外的辅助增强组件。

这里默认基础管线已经由 [[2026-06-03-SceneTAP接入与实验设计|SceneTAP 渲染流程]] 提供，包括：

- 自动搜索适合植入文字的区域。
- 使用 `TextDiffuser-2` 将短文本融入环境并生成新图。

因此，这里的问题不再是“如何把文字写进图里”，而是：

$$
\text{如何设计额外的 patch，使模型更容易关注、读取并服从攻击词}
$$

## 研究目标

希望回答三个问题：

- `patch` 能否在不明显破坏环境自然性的前提下，提高 ASR。
- `patch` 的增益究竟来自视觉注意力引导，还是来自功能性语义提示。
- 当前失败的 `red_box` 是不是只代表一种无效设计，而不是整条 `patch` 路线无效。

## patch 的角色定义

这里把 `patch` 定义为：围绕攻击词额外加入的、用于增强攻击效果的小型视觉组件。

它不负责替代攻击词，也不负责重新承担 `SceneTAP` 的载体搜索与融字生成任务，而是负责做额外增强。

更具体地说，`patch` 可能承担三种功能：

- 注意力引导：让模型的视觉处理更容易落到文字区域附近。
- 语义提示：让模型把这段文字看成“功能性区域”而不是普通背景文字。
- 结构绑定：让攻击词和周围局部结构形成一个整体对象，提高被整体读取的概率。

## 设计空间

### 一类：显著性增强型

目标是轻量提升文字区域邻域的可见性，但不引入过强的独立语义。

可测试形式：

- 弱边框。
- 半透明底板。
- 局部高亮块。
- 局部对比增强带。
- 轻度阴影或描边结构。

这类设计的风险是：模型只注意到 patch 本身，而没有进一步读取文字。

### 二类：语义提示型

目标是让模型把该区域当成“带功能的提示区域”。

可测试形式：

- 箭头。
- 小图标。
- 按钮式小框。
- 提示标签。
- 状态框。

这类设计的风险是：语义太强会破坏环境自然性，或者让 patch 自己成为主要关注对象。

### 三类：结构绑定型

目标是让 patch 和攻击词共同组成一个局部结构，而不是“文字 + 外围独立装饰”。

可测试形式：

- 标签框。
- 角标。
- 小贴签边缘。
- 局部信息卡片边框。
- 与物体边缘对齐的附着结构。

这类设计更接近真实世界里的贴纸、标签或说明牌，也更符合物理可落地约束。

## 不建议优先做的方向

基于当前判断，下面几类方向不适合作为近期主实验：

- 大幅修改攻击词本身。
- 大范围重做载体搜索逻辑。
- 大范围重做字体风格。
- 直接开展真实物理实验。
- 把“文字不够贴合环境”的问题当成近期主线去改 `TextDiffuser`。

这些内容不是没价值，而是当前阶段的性价比低于 `patch` 主线。

## 变量控制原则

为了判断增益是否真的来自 `patch`，实验里必须严格控变量。

建议固定的部分：

- 固定图片集合。
- 固定 query 集合。
- 固定 `SceneTAP` 的区域搜索流程。
- 固定 `TextDiffuser` 的基础生成流程。
- 固定一组主攻击词。

建议小范围变化的部分：

- `patch` 类型。
- `patch` 的大小。
- `patch` 与文字的相对位置。
- `patch` 的透明度或视觉强度。
- 攻击词模板的小范围变体。

## 最小实验矩阵

第一轮不适合把设计空间铺得太大，建议先做一个最小矩阵。

### patch 类型

- `none`
- `weak_border`
- `soft_bg_plate`
- `arrow_hint`
- `status_tag`
- `bound_label`

### 相对位置

- `left`
- `right`
- `top`
- `bottom`

### 强度

- `weak`
- `medium`

### 攻击词模板

- 固定 1 组主模板。
- 额外保留 2 组轻微变体模板。

这样第一轮的目标不是找到全局最优，而是尽快回答：

- 有没有哪一类 patch 明显优于 `none`
- patch 的效果是否高度依赖相对位置
- patch 的效果是否对视觉强度非常敏感

## 第一轮实验重点

第一轮建议优先回答“patch 是否有效”，而不是一开始追求最优 patch。

适合先看的结论：

- 哪类 patch 能把 ASR 从 `20%` 到 `30%` 稳定推高。
- 哪类 patch 会让 `patch bbox` 上升但 `text bbox` 不上升。
- 哪类 patch 会导致输出更不稳定或更容易偏离预期。

如果第一轮结果显示只有个别 patch 有增益，再进入第二轮精细搜索。

## 指标体系

除了 ASR，建议继续沿用 [[2026-06-06-注意力Patch实验计划|已有注意力实验计划]] 里的三层区域分析。

统一统计以下区域：

- `text bbox`
- `patch bbox`
- `expanded bbox`

统一统计以下指标：

- `cross_attention_ratio`
- `cross_mean_attention`
- `vision_attention_ratio`
- `vision_mean_attention`

如果条件允许，还可以补两个辅助指标：

- 输出一致性：同一配置在多次采样下是否稳定。
- 目标词命中率：即使未完全成功，是否更频繁出现目标攻击词。

## 结果判读规则

### 理想有效的 patch

满足以下现象时，可以认为 patch 真正起到了增强作用：

- `text bbox` 注意力上升。
- ASR 同步上升。
- `patch bbox` 不是唯一显著上升区域。
- 输出结果更稳定，而不是更随机。

### 伪有效的 patch

满足以下现象时，说明 patch 只是“显眼”，而不是“有效”：

- `patch bbox` 上升很多。
- `text bbox` 不升，甚至下降。
- ASR 不升，或者波动很大。

### 干扰型 patch

满足以下现象时，说明 patch 正在破坏原始攻击词：

- `patch bbox` 与 `expanded bbox` 都上升。
- 但模型对文字内容的读取更差。
- ASR 下降。

这类结果反而很有价值，因为它可以支持一个明确结论：并不是所有辅助组件都能增强攻击，很多设计只是在竞争视觉资源。

## 第二轮实验怎么做

如果第一轮已经找到 1 到 2 类有潜力的 patch，第二轮再做局部细化：

- 调整 patch 与文字之间的距离。
- 调整 patch 面积占比。
- 调整 patch 是否与文字直接接触。
- 调整 patch 是否与场景结构对齐。
- 对不同类型 query 分别评估稳定性。

第二轮的目标不再是证明“patch 是否有效”，而是分析“为什么这类 patch 有效”。

## 与短文本搜索的关系

短文本模板搜索依然保留，但这里只把它当成辅助变量。

更合适的做法是：

- 先固定一组表现中等稳定的攻击词模板。
- 在 patch 主线跑通之后，再用少量模板变体做交叉验证。

这样可以避免把“文本改好了”误判成“patch 有效了”。

## 与环境贴合度问题的关系

当前生成结果里，文字与环境不够贴合，确实可能会压低 ASR。

但这条线当前更适合这样处理：

- 先把贴合度问题当成误差来源记录。
- 观察贴合度差的样本是否更容易失败。
- 如果相关性明显，再把它上升成一个独立限制项。

也就是说，这部分先不作为近期主实验，而是作为当前方案的限制和生成侧后续接口。

## 近期执行顺序

建议按下面顺序推进：

1. 固定 `SceneTAP` 基础流程与主攻击词模板。
2. 构造 5 到 6 类代表性 patch。
3. 先做小样本筛选，淘汰明显无效或明显干扰的 patch。
4. 对剩余 patch 做正式的注意力与 ASR 统计。
5. 最后再用少量短文本模板做交叉验证。

## 预期能得到的结论

如果实验顺利，最终至少可以得到下面几类结论中的一种：

- `patch` 路线有效，并且某类设计能稳定提高 ASR。
- `patch` 路线部分有效，但增益高度依赖位置或强度。
- `patch` 路线在当前 `SceneTAP` 基线下难以提供显著增益。
- 当前主要限制不在辅助组件，而在生成质量或短文本本身。

无论结果是哪一种，只要变量控制得足够清楚，这条线都能形成比较扎实的研究结论。
