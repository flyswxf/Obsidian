- 现在自动化不敢直接跑测试，一个关键原因是执行输出不是流式可见的。

- 这会带来几个直接问题：
  - 出现明显异常时，不能及时中止
  - 用例卡死时，自动化侧看不到卡在哪一步
  - 必须等到整段执行结束后才能拿到结果，排查很慢

- 这块的目标不是先做 AI，而是先把执行器改成“边跑边看”。

- 推荐的能力拆分：
  - 实时逐行读取 stdout / stderr
  - 把日志立即打印或写到文件
  - 支持超时中止
  - 支持关键字触发中止
  - 支持在执行期间插入人工观察

- 如果底层是 Python / pytest，优先排查输出缓冲问题：
  - 关闭 stdout capture
  - 使用无缓冲模式
  - 确保 print 和日志能实时刷新

- 执行器层面建议做一个统一入口，至少包含这些能力：
  - 启动测试命令
  - 持续读取输出
  - 记录开始时间、当前阶段、最后一条输出时间
  - 判断是否长时间无输出
  - 到达阈值后 terminate / kill

- 可以先定义几类常见中止条件：
  - 超过总执行时长
  - 连续一段时间没有任何输出
  - 命中特定错误关键字
  - 命中已知危险路径，例如会持续制造脏数据或破坏环境的操作

- 做完这一步之后，自动化才真正具备下面这些基础能力：
  - 不用等结果一次性吐出来
  - 可以尽早发现跑偏
  - 可以在卡住时留下更有价值的中间证据
  - 可以给后续 AI 分析提供结构化时序日志
