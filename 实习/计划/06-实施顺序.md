- 当前更适合按“先降恢复成本，再提高自动化程度”的顺序推进。

- 第一阶段：验证网络访问方案
  - 目标：确认是否可以通过跳板机 + 内网 IP 代替 4 个 EIP
  - 验证结果如果可行，后面的自动化复杂度会明显下降

- 第二阶段：做环境申请编排
  - 目标：把创建实例、查节点、改密码、生成配置串成一个脚本
  - 成功标志：新建一套环境时，不再需要手动逐条敲命令

- 第三阶段：改造测试执行器
  - 目标：让测试执行过程具备流式输出、超时中止、异常中止能力
  - 成功标志：卡死或跑偏时可以及时发现并停掉

- 第四阶段：补环境预检和回收
  - 目标：正式跑用例前先做健康检查，跑完后自动回收或复位资源
  - 成功标志：环境脏掉的概率降低，资源利用更稳定

- 第五阶段：做失败归因自动化
  - 目标：先用规则检查处理大部分环境类问题，再引入 AI 做总结
  - 成功标志：失败后不用第一时间人工登录每个节点手查

- 一个较现实的短期顺序可以是：
  1. 先做“跳板机 / 内网 IP 可行性验证”
  2. 再做“环境一键创建 + 配置生成”
  3. 然后做“流式执行 + 超时中止”
  4. 最后做“只读排障 + AI 辅助分析”

- 这样推进的原因：
  - 越早解决 EIP 问题，越容易并行测试
  - 越早降低建环境成本，越敢让自动化去试
  - 执行和分析放在后面，整体风险会小很多
